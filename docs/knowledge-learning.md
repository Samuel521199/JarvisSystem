## K2 首期知识与记忆范围

第一版运行时知识库以“知道当前版本会什么、查到正确来源、记住明确要求”为目标，采用已有原始资料、SQLite 元数据与全文检索的设计。向量索引、互联网批量采集和知识图谱不是进入 K2 的必要条件。现有种子文件提供基础内容，但不代表检索、纠错或长期记忆服务已经运行。

| 输入 | 入库与使用方式 | 首期边界 |
|---|---|---|
| 激活发布的知识和文档 | 通过发布清单/文档 manifest 确定范围，记录文档 ID、版本、摘要、稳定锚点、状态和证据引用 | 同一文档中的 implemented 与 proposed 内容分别标注；描述未来能力的段落不能作为当前可执行能力证明 |
| 当前技能与系统清单 | 读取已准入技能、包版本和实际探测状态，回答“现在能做什么” | 未安装、planned 或不兼容技能可以解释，不进入可执行工具列表 |
| 主人明确偏好与纠正 | 记录来源事件、适用范围和有效版本；提供查看、修正与遗忘入口 | “今天这次用英文”默认只约束当前会话；不能推断成永久人格或授权改变 |
| 任务结果和失败经验 | 从已确认回执/产物提取候选经验，保留具体版本与任务范围 | 一次成功不直接晋升为普遍规则；失败证据不因新成功被覆盖 |
| 会话内容 | 0.1.24 普通会话文字自动归档并展示保存状态，临时会话只保留在页面；完整边界见[当前会话归档](#local-chat-archive) | 会话、任务账本和长期事实分开；新对话或清空会话不隐式删除任务审计，也不自动创建长期事实 |

检索顺序为：按来源范围、版本、状态、撤回标记和隐私先过滤，再按查询相关性排序，最后输出最少必要片段与引用。规则由受保护加载路径执行；检索只解释规则，不决定规则是否生效。代码、配置与有效文档不一致时显示冲突，以实际能力和版本证据回答，不让模型自行选择较乐观的描述。

索引是派生物，损坏时可从指定原件重建；重建失败时展示暂不可检索，不能扩大到扫描整个磁盘。失效、草稿、旧发布、调试文件、凭据和 NPC 记忆默认不进入正式项目检索。主人要求遗忘或修正后，同步失效相关摘要和索引；保留策略按[遗忘与备份](#memory-data-5)实施。

本地检索与外发是两次不同决定。只有满足记录的 `external_processing` 范围，检索片段才能加入所选云模型上下文；自动切换供应商时必须重新核验目的供应商是否在范围内。被禁止外发的材料保留本地处理或等待，不因已有云端聊天凭据而自动上传。首期不自动联网学习；后续学习沿用[晋升流程](#continuous-learning-2)。

### 种子知识、规则与能力运行入口（0.1.28）

[RuntimeCatalog](../runtime/node-host/jarvis_core/runtime_catalog.py)提供独立、按需、只读的初始资产视图。只读取固定发布清单和知识/规则/技能三份文件，每份最多 64 KiB；先核对宿主固定的清单摘要，再核对资产摘要，不沿来源链接读取其他文档或执行清单中的入口。损坏、缺失、超限或链接文件使本次视图不可用并清空内容，不沿用旧成功结果。摘要校验依赖宿主代码可信，不能证明同用户恶意修改下的隔离或发布签名。

本机设置可查询 5 条初始知识、6 条规则说明、4 项能力与 4 项技能，并查看版本、来源和状态。种子仍为 K0 的历史基础资料：规则作用域是 K0/K1，实际准入由现有宿主执行器判断；它不重新启用已延期的认证或全局监督。知识和技能文字不能授予权限，种子描述为 available 也不自动获得执行权。

当前状态查询对应已有本机入口；样例目录能力标为“执行前检查”，仍须核对 Worker、目录和当前准入；产物输出仅供宿主内部使用；候选构建仍是 planned。所有条目的 `chat_callable=false`，本增量不增加模型到工具的调用入口。用户登记的 MCP/技能保持独立，只观察其登记状态，不将任意 SKILL.md 作为受信规则加载。

聊天按次取得种子校验是否可用的简短宿主说明，云端和本地均不自动接收种子正文、规则、文件路径、扩展配置或个人事实。0.1.62 起，`查询三库：关键词` / `查看能力` 可通过本机确定性分流查询种子知识、规则、技能及当前受限能力，附来源与版本；旧 K0/K1 种子与当前受限成长冲突时同时解释历史范围，不能把通用规划能力报成可执行。派生 `reference-index.json` 只保存校验来源的摘要与词项，最多 256 KiB；查询重验来源，索引损坏可重建、磁盘不可写则内存降级，种子校验失败不使用旧索引。单次最多 8 条、12 KiB 答复；不自动向云端发送正文，也不是全项目语义索引或规则执行器。监控缓存、字段和边界归[模块观察契约](contracts.md#module-monitor-contract)，验证归[本轮证据](delivery-validation.md#runtime-entry-evidence)。

<a id="local-chat-archive"></a>
### 当前本机会话归档（0.1.24）

[ConversationStore](../runtime/node-host/jarvis_core/conversations.py)是独立、无模型依赖的 SQLite 文字归档模块；与任务账本、项目文件导出和事实库分开。普通会话在页面提交消息、收到回答/错误/停止结果后异步保存结构化文字快照，保存确认后才显示“已存本机”。同一会话的最近完整轮次可以在刷新后继续作为聊天历史使用；不会自动检索或注入其他会话。会话要求随已发送文字保存，未发送草稿、附件原件和浏览器 DOM 不入库；用户或模型已经引用在聊天正文中的附件内容仍属于归档文字。

刷新时可恢复当前归档，左侧可打开其他本机会话。带附件的消息保留“附件未归档”标记；恢复后该轮不进入模型历史，需重新添加附件。没有完整回答的轮次、错误/停止提示仍可回看，但不作为成功对答重放。临时会话不归档，关闭/刷新即失；该选项不删除模型供应商已有处理记录。

写入版本冲突或存储失败时保留页面内容并显示失败，可手动重试；不谎报保存完成，不将失败转为重新调用模型。当前由页面发起保存，若在确认前强制关页/断电，最近显示内容可能尚未落盘；后台完成但页面未收到的模型回答也不由本归档服务自动补取。容量用量达到上限后停止新增归档并提示，不暗中裁剪旧记录。具体字段、限额和删除的并发语义归[归档契约](contracts.md#conversation-archive-contract)。

“删除此会话”删除对应归档正文、摘要指纹和页面缓存，留下不含正文的删除标记，阻止旧页面的迟到保存让它复活。不删除任务审计、模型用量记录或用户导出的文件；也不承诺擦除系统/用户已有备份或供应商副本。当前没有向量索引、跨设备复制或自动整理服务。验收见[0.1.24 证据](delivery-validation.md#conversation-archive-evidence)。

<a id="explicit-memory-runtime"></a>
### 明确事实记忆：首个运行增量（0.1.25）

[MemoryStore](../runtime/node-host/jarvis_core/memory.py)在运行数据目录中使用独立 `memory.db`，提供明确保存、修改、忘记和中文片段搜索。来源固定为 `owner_explicit`，表示主人在[记忆面板](interaction-persona.md#explicit-memory-ui)或 [0.1.39 明确聊天指令](interaction-persona.md#personal-core-ui)中保存，不表示系统已经独立核实内容。普通闲聊只自动归档，不自动提取事实。记忆文本作为带标记的背景资料进入 user 上下文，不升级为 system 指令、规则或工具回执。

| 当前行为 | 已实现边界 |
|---|---|
| 通用与项目范围 | 无项目 ID 的事实用于普通会话；项目事实只在对应已登记项目中读取。通用偏好跨项目可用，项目事实不自动推广；0.1.33 的跨项目增量见[联合视图](#memory-view-runtime)，私人域与 NPC 域仍待实现 |
| 本地与外发 | 新记录默认仅本地模型可用；面板逐项选择云端接入方，使用配置中的 provider ID。每次候选路由/回退重新过滤；服务端从事实库读取正文，不信任客户端提交“允许使用”的正文 |
| 中文查找与装配 | 名称和内容做 Unicode NFKC、大小写归一后的字面片段查询，无分词/向量/语义召回。0.1.33 聊天按[联合视图规则](#memory-view-runtime)选择完整记录；面板仍为字面片段查询 |
| 修订与遗忘 | 乐观版本检查避免旧页面覆盖；相同请求可重试，删除标记阻止已忘记 ID 被迟到保存复活。只保留当前正文和不含正文的修订回执，尚非双时间历史事实库 |
| 历史引用传播 | 回答携带所用记忆的 ID/修订，并随会话归档；后续回答继承这些引用。发现修订变化、删除、跨项目、接入方不允许或关闭记忆时，整个相关历史轮次不再自动发送，并显示省略提示 |
| 临时会话与失败 | 临时会话不装配记忆，面板禁用保存/忘记；显式查看面板仍可读取当前范围列表。记忆读取失败会提示且不派发本轮模型请求，可关闭记忆继续普通聊天 |

0.1.39 的聊天操作复用同一事实库和事务写入者。操作仅匹配本轮完整的显式指令，不扫描历史、附件、引用示例或模型输出来发现写入要求；纠正/忘记在所选单一范围内精确匹配名称、正文或 ID，重名时不猜测。指令轮次（包括本地查看结果）归档时标记为个人控制消息，在当前页面和刷新恢复后都不加入模型历史，避免绕过外发限制或重新带回已忘记的正文。普通模型回答继续沿用既有修订引用失效规则；手动复制旧正文再次发送不在此自动排除机制内。

这一增量实现的是明确事实在新会话、模型切换和进程重启后的按范围使用；不是读取全部历史聊天、自动总结共同经历或跨设备记忆同步。

资源与容量边界只维护在[运行接口](contracts.md#explicit-memory-contract)与[个人指令扩展](contracts.md#personal-core-contract)。本模块复用标准库 SQLite 和已有 schema 校验器，没有新模型下载、数据库服务、常驻整理进程或网络客户端；性能证据见[本轮验收](delivery-validation.md#explicit-memory-evidence)，不能据“没有新增依赖”推断整机性能已达标。

遗忘清除当前事实正文及搜索文本；修订回执只留标识、操作和时间。既有聊天正文、用户导出、供应商副本和系统备份不属于此删除操作。已经发出的模型调用无法召回；新请求按当次读取快照过滤，调用途中发生的改动在下一次装配生效。当前不存在向量或摘要索引，无需清理这类派生物。

历史引用保护覆盖当前客户端管理的上下文链，不是同用户恶意客户端的隔离边界，也不能识别用户手动粘贴、无引用的旧文本。模型文本仍可能猜测或记错，不能据自然语言“我记住了”宣称写入成功。完整自动记忆与多设备冲突/删除传播仍按下文设计推进。

<a id="project-retrieval-runtime"></a>
### 项目文档检索：带来源的运行增量（0.1.26）

[KnowledgeStore](../runtime/node-host/jarvis_core/knowledge.py)是独立的项目文档读取与检索模块。主人在[项目资料面板](interaction-persona.md#project-knowledge-ui)明确登记项目内 UTF-8 Markdown、纯文本或 RST 文件，0.1.27 的资源工作台会按需列举文件树，但不会因此自动纳入 AI 检索。`project-sources.db` 只保存项目/相对路径、使用范围、登记修订和撤出标记，不复制文档正文，不自动生成 Wiki、知识事实或向量索引。

每次查询和每次模型候选调用都先按当前项目及允许的接入方选择登记，再读取有界文件快照并计算内容摘要。Markdown 按标题和有界行段切分；TXT/RST 使用有界行段。检索按英文词项、中文连续双字片段与标题匹配排序，零命中不自动塞入整份文件；这只是词法基线，不是语义理解或完整代码分析。查询使用本轮消息的前段，超出处理长度的部分不参与检索；具体限额只在[运行契约](contracts.md#project-knowledge-contract)维护。

回答上下文中的每段资料带来源登记 ID、登记修订、内容 SHA-256、相对路径、标题和行号。模型被要求用 `[P1]` 等当前回答内的标记引用；界面直接展示本轮实际提供的来源，不依赖模型生成链接。点击来源会重新读文件并核对摘要，已变化时显示过期，不把当前不同内容伪装成当时证据。来源存在只证明资料被提供，不能证明模型解释正确，也不能将原文中的 proposed 计划升级为已实现事实。

模型回答及后续回答继承使用过的资料引用。切换项目、改用未允许的接入方、关闭项目资料、启用临时会话、登记撤出/修订或文件内容变化后，整个依赖旧来源的历史轮次不再自动重发；刷新恢复归档仍保留此关系。该机制和[明确事实引用链](#explicit-memory-runtime)并行，分别过滤后才进入统一上下文预算。实际提供的资料摘录不另存到归档元数据，已经被模型引用进回答的文字仍属于聊天正文。

读取时文件缺失、超大、编码不支持或预算不足会形成可见缺口；不复用旧正文。当前没有后台监听器：修改后在下一次检索读取新内容，删除或迁移后需要调整登记。来源移到另一位置应撤出旧项、登记新项，不能静默让旧 ID 改指另一个文件。撤出不会修改原文件，也不会删除既有聊天、导出、备份或供应商副本；已经派发的请求仍不能撤回。

临时会话不自动装配资料，也不修改登记；用户明确打开面板仍可做本机查找/预览。资料是非执行的外部文本，不授予工具权限。路径/链接与同用户进程的实际边界归[读取边界](security-sovereignty.md#project-knowledge-boundary)。本模块没有引入常驻数据库、Embedding 或外部知识运行时；实测与限制见[0.1.26 验收](delivery-validation.md#project-knowledge-evidence)。

0.1.26 完成单项目检索基础；0.1.33 的跨项目增量见[联合视图](#memory-view-runtime)，种子状态加载见[种子入口](#seed-runtime-entry)。种子正文的模型检索、源码符号分析、自动知识编纂、自动记忆提取和共同体同步仍未完成。下文 KnowledgeCompiler 是后续生产者；不能把当前的段落读取称作 OpenWiki 全量集成。

<a id="memory-view-runtime"></a>
### 有界跨项目知识视图（0.1.33 implemented）

[MemoryView](../runtime/node-host/jarvis_core/memory_view.py)在每次提问、每个实际供应商候选下，将明确事实和登记文档组合成临时视图。它协调既有 MemoryStore / KnowledgeStore，不创建第三个事实库、向量库、提取器或后台同步服务。页面入口见[联合查询使用方法](core-bootstrap.md#memory-view-entry)，机器字段与共享限额归[运行契约](contracts.md#memory-view-runtime-contract)。

| 语义 | 当前行为 |
|---|---|
| 范围由谁决定 | 本机主人页面明确选择已登记项目；当前项目必须包含在范围中。模型生成的 ID 不扩大读取范围。不改变事实或文件永久分享策略，不自动合并项目 |
| 事实与资料如何组合 | 先按项目和实际 provider 排除候选；事实按本轮词项相关度优先、同分保持更新时间顺序，再补背景偏好。通用事实只出现一次。文档只读取已登记文本，按词法匹配取完整段落，每个匹配项目的最佳段落先获得一次选择机会 |
| 来源与缺口 | 事实带 ID/修订及项目名；文档带项目 ID/名、源修订、内容摘要和行号。同名文件仍可区分。每个请求项目报告 matched / partial / no_evidence；没有允许来源、没有词法匹配或预算装不下都可能无证据，不能把它说成该项目没有相关知识 |
| 新鲜度与历史 | 读取期间撤出/修改来源权限会在快照返回前被再次核对。新路由重新建视图；范围收缩、遗忘或资料变化使相关旧历史整轮退出。点击归档引用仍定位原项目并重验内容，不能用当前项目冒充来源 |
| 页面生命周期 | 额外项目选择仅本页当前会话有效；切换会话/刷新复位。临时会话不自动携带事实/资料，仍可显式本机预览当前项目文档；预览不调用模型 |
| 真实边界 | 多库与文件读取不是原子事务，snapshot_atomic=false；检查后或模型调用中再发生的修改在下一次装配生效。当前本机个人使用模型无独立多用户 ACL，不宣称能阻止同用户恶意客户端自行重贴旧内容 |

0.1.62 的事实相关性在来源、项目、用途和接入方过滤之后计算：标题/正文词项、少量明确主题词组和短指代的最近有效引用，零命中的普通事实不填满上下文；通用语言/回答风格配置仍可适用。矛盾的相关事实保留各自来源，不按新旧自动决定真伪。短指代也重新读取当前修订，遗忘与撤权优先。

完整身份、人格/模拟域、因果/时间水位、冲突裁决、语义召回、源码知识编纂与多设备同步仍为 proposed。当前实现证明有限范围的联合装配，不代表“记忆完整理解了所有项目”；模型正文引用仍可能遗漏，界面显示的是实际提供的来源，不是回答正确性的证明。验收与小模型限制见[0.1.33 证据](delivery-validation.md#memory-view-evidence)。

<a id="selective-memory-policy"></a>
### 长期记忆的选择原则（accepted 方向，提取器未实现）

**会话自动归档不等于把每句话变成长期记忆。** 原始记录帮助回看与纠错；长期事实应由独立 memory-curator 根据来源、适用范围、复用价值、时效和冲突选择，保留可解释的“记住/暂存/忽略/替代”结果。不能因为一句话出现过就永久记住，也不能因为模型自称重要就晋升。

| 信息 | 长期记忆处理方向 |
|---|---|
| 主人明确要求记住的内容、反复确认的稳定偏好 | 形成带来源与范围的候选，允许查看、纠正和遗忘；一次性要求仍限定本次 |
| 项目目标、设备配置、已确定的决定和未完成承诺 | 按项目/设备及有效期归类，更新时保存替代关系；未完成事项不能因近期未提及而静默遗忘 |
| 已核验的任务经验 | 引用真实回执、版本和适用条件；与模型生成的建议分开 |
| 问候、礼貌套话、重复解释、无后续用途的闲聊 | 通常不提取长期事实；聊天归档可保留供回看，用户可删或使用临时会话 |
| 模型猜测、未经核实的网页说法、互相矛盾的信息 | 不直接晋升为已确认事实；保留来源与待核验/冲突状态 |
| 已过期内容、被主人纠正或要求忘记的信息 | 使旧事实及其派生检索失效；按既有遗忘规则处理，不靠摘要复活 |

优先使用确定性去重、来源/范围/时效过滤；需要语义判断时再调用轻量本地模型或获准路由，异步处理、不阻塞说话。预算不足则保留待处理状态，不伪造“已理解并记住”。用户不必逐条点击“保存回答”；未来界面提供可检查的自动记忆变化入口。0.1.25 已实现上述会话归档与面板明确事实记忆，尚不能自动判断每条聊天内容是否值得长期记住。

<a id="memory-selection-design"></a>
## 单机与共同体的记忆选型设计

本节为 2026-10-18 复核后的 proposed 设计，具体开源组件与许可只在[选型表](stack-project-layout.md#memory-open-source)维护。基本原则是：**原始证据可追溯，事实可纠正，索引可重建，节点可离线，联网后可解释地合并。** 共享一个向量库只能提供相似搜索，不能独自完成这些职责。当前已实现[本机会话归档](#local-chat-archive)、[明确事实子集](#explicit-memory-runtime)及[单项目文档检索](#project-retrieval-runtime)；[有界跨项目视图](#memory-view-runtime)已接入；下述完整时态事实、域/版本视图和同步尚未接入运行。

<a id="memory-current-gap"></a>
### 从现有能力改造：保留什么，先补什么

这次调研不替换正在使用的数据库，也不将已实现子集改称完整记忆系统。现有能力与后续缺口如下；实施顺序只在[核心 K2 工作包](core-bootstrap.md#next-implementation)维护。

| 当前落点 | 已有基础 | 后续改造要求 |
|---|---|---|
| 会话归档、明确事实、基础人格 | 会话可回看，事实可记住/纠正/忘记，表达偏好持久化 | 人格表达配置和现实事实保持独立；读取共同经历不要求用户先创建项目 |
| `personal_candidates.py` / `semantic_candidates.py` | 中文规则与按需 LLM 候选并存；0.1.60 共用[本地核对与事务检查](contracts.md#memory-candidate-review-contract)，确认才写入 | 补独立留出和复杂表达验证；已有明确记忆指令保持确定性，词项比较仍会漏检 |
| `memory.py` / `continuity.py` | 来源失效、同源撤销、旧语义预览屏障；新增显式沿用/替代及来源绑定；接续有原来源检查 | LangMem/Mem0 已作公开样例对照；旧事实不猜造引用。完整多来源证据、语义等价撤销和跨节点删除仍待实现 |
| `memory_view.py` / `knowledge.py` | 事实与登记文档按范围/provider 过滤；0.1.47 另有[事实分类、到期与主人日常/工作用途](#memory-domain-runtime) | 补自动提取、完整受众隔离、中文语义改写、相关经历及冲突解释；当前实现不等于 FTS5、向量或完整时态检索已完成 |
| 已有关联任务与成长记录 | 接续可以核对真实任务状态，限定成长有回执 | 总结经验必须引用真实结果；“下次继续”与定时执行是不同意图，记忆不能自行创建未请求的提醒或行动 |
| 本地 SQLite 和模块接口 | 可独立读取既有资料 | 增量补迁移版本、候选来源和删除对账；不一次换掉全部库，不先建立重型集群 |

改造先用独立实验存储比较新提取器；对用户资料的试用只处理已允许的新增片段，已有历史不自动全量重新解释。新旧实现以相同输入作影子比较，影子输出不写生效记忆。切换保留事实 ID、修订和现有请求幂等回执；旧来源无法定位时允许回看或人工修订，不能伪装已迁移完整。回退实现也须保留切换后的纠正与删除，不能恢复过时事实。详细替换语义归[组件契约](contracts.md#memory-provider-contracts)。

补充个人/工作分域时，旧通用事实不能批量改为“所有用途和受众共享”。保留原 ID、项目/provider 限制与已有手动使用方式；新增分类或输出资格缺失的记录标为待归类，面向他人/公开的全新用途先排除或经明确决定补齐。按需迁移并提供差异预览，不自动扫描全部历史建立主人画像；降级组件不能用忽略新字段的方式绕过范围限制。

<a id="memory-operating-cycle"></a>
### 交流、经历、事实和 Wiki 如何一起工作

以下是完整目标流程，不是新增后台服务已经运行。它沿用[分层](#memory-data-1)，把需要即时响应的读取与可以延后的整理分开：

| 信息职责 | 写入/更新时机 | 回答时如何使用 |
|---|---|---|
| 近期交流与工作状态 | 当前会话追加；任务状态由既有账本更新 | 有界窗口直接读取；必要摘要可回查原消息，未结任务引用不因压缩丢失 |
| 原始情景经历 | 允许保存的交流与工具回执到达后 | 按人、主题、时间和作用域定位原片段；原话只是“当时说过什么”的证据 |
| 长期事实与偏好 | 明确操作立即处理；自然描述经候选整理与晋升规则处理 | 使用当前有效、适用范围内的版本；历史事实仅在明确历史问题中使用 |
| 主题知识/Wiki | 新资料、源版本变化或明确整理任务触发 | 先给简述与章节目录，按需展开，并可追溯到来源；资料过期时提示并回查 |
| 经验与技能 | 有真实完成回执后形成经验候选 | 已验证经验帮助决策；生成技能仍走独立构建、测试、发布流程 |

一次自然交流的设计流程是：

1. **登记可用来源。** 临时会话与不允许保存的内容不入后台队列；普通交流保留既有归档策略。同一消息按主张标记主体、角色、范围和时间，原件保存一次；网页正文或其他 Agent 的话不能变成主人指令。归属见[信息分类](#memory-domain-catalog)。
2. **先回应，再整理。** 当前问题通过 MemoryView 取相关偏好、经历、知识和真实进度，按用途、消费者及实际目的地过滤；后台整理失败不阻塞回应，也不伪称保存成功。面向他人的产物另按[输出边界](#memory-use-boundary)装配，不继承私人历史。
3. **对变化产生候选。** 先做重复、无价值和明显不适用过滤，确需语义理解时调用 MemoryExtractor；输出有依据的类别、适用条件及“为什么值得保留”，不复制整段回答为主人事实。未明确范围的内容留待核对，提取失败保留允许的原件和待处理状态。
4. **按类别生效。** 明确记忆操作保持原语义；未来启用自动整理时，主人可配置低歧义偏好自动生效并可撤销，含糊、相互冲突和敏感推断进入待确认。当前 0.1.43 的候选仍需确认，不因本文变成自动保存。
5. **更新派生内容。** 事实提交后标记受影响索引、画像、摘要和章节为待更新；只整理相关片段。需要跨域复用时走[共享连接](#memory-sharing-bridges)，知识编纂不覆盖原件，关联图不反向改写事实，未更新视图显式报告缺口。
6. **纠正与遗忘优先。** 生效事实可立即退出召回，再清理相关候选、缓存和索引。后台任务提交前再次检查来源版本和撤销，防止在“忘记”之后把同一来源重新提取回来。
7. **有变化才协同。** 未来已配对节点按允许范围交换事件和原件引用，各自维护索引；断网仍使用本地资料，重连合并不等于重新执行历史任务。协议只在[共同体章](federation.md#memory-replication)定义。

自动保留的价值判断考虑明确意图、未来复用、稳定性、约定和共同经历，而不是只挑“工作上有用”的信息。一次重要的生活经历可以有伙伴价值；一句玩笑、角色扮演或短暂情绪不因此成为永久人格标签。主人切换表达人格可以共享允许的现实背景，NPC 的虚构记忆始终留在对应世界。自动关联和模型反思只是辅助解释，不提供事实真实性或新行动权限。

“忘记某条记忆”与“删除原始聊天”继续区分：前者撤销长期使用，后者按归档策略处理原件；未来需用最少必要的撤销标识阻止同源再提取，并展示尚未处理的离线副本或保留范围。不能为了防复活而在墓碑中保留被删除的完整敏感正文，也不能宣称已经抹去外部供应商、用户导出和所有备份。

记忆自检检查来源失效、冲突、孤立引用、索引水位、过期候选和队列积压；自愈可重建派生索引，不能编造丢失原件或自动裁决冲突；进化只提出新分段、提取、召回和组织方式，经固定对照后替换。若知识重组没有可测收益，保留原结构，不为“自主成长”不停改写记忆。健康与发布完整规则分别见[维护章](health-maintenance.md)和[进化章](evolution-release.md)。

<a id="section-c30fc1f84bda"></a>
### 分层保存，避免把所有东西都变成聊天摘要

沿用[数据分层](#memory-data-1)，将原件放入带摘要的对象存储，事实/修订和事件放入本地事务库，关键词/向量/关系放入可重建视图。任务工作记忆引用既有任务账本；规则、人格配置与技能包保留各自版本权威，检索结果不能改写 G0 或授予能力。

事实使用“何时有效”和“何时得知”两个维度：主人今天纠正上周的项目地址，应能分别回答“上周实际地址”和“当时系统知道什么”。这里是我们的事实建模要求；Graphiti 的时态方法可供实现参考 [S94](references.md#s94)，不等于必须先部署图数据库。相似表达不能仅凭向量距离合并为同一实体，也不能把 Agent 猜测提升为主人确认。

<a id="memory-scope-model"></a>
### 先理解主人，再按场景读取个人与项目记忆

**完整目标，proposed；当前实现边界见[现状表](#memory-current-gap)。** 推荐统一记忆接口与事实管理规则，在数据中区分主体、用途、项目/世界和使用许可，再为每次请求建立有界视图。个人会话不要求先创建项目；项目中的一句话也不天然是工作事实。同一个助手可以理解主人全部已授权生活与工作范围，但每次回答、交付物和外部调用只使用该用途允许的内容。

分类按**具体片段/主张**进行，不把整场会话永久判成“生活”或“工作”。“今天有些累；A 项目发布推迟；以后周报先给结论”可以产生临时状态、项目决定、交流偏好三个不同候选。原件仍保存一次；多项引用共同原件不意味着可以向某个消费者返回整段原话。尚不明确的范围保持待归类，不默认设为全局共享。

#### 轻量事实分类与用途筛选（0.1.47）

**implemented；局部验证见[分类与资源证据](delivery-validation.md#memory-domain-evidence)。** 保留原 `memory.db`，只在已有事实 document 中增加分类，确定性判断独立于 [memory_policy.py](../runtime/node-host/jarvis_core/memory_policy.py)。没有新增依赖、模型、向量服务、定时扫描或每类一个常驻 Agent。仍受 1,000 条有效事实、每轮最多 20 条/6,144 字节的既有上限约束，不能由此次实现推导百万条规模。

- **类型与主体：**个人事实、偏好、共同经历、临时状态、项目资料、工作结果描述、共用经验、他人资料、虚构角色资料。主人、项目、他人、角色按类型明确区分；他人/角色必须标注名称，项目资料/结果必须绑定项目。这是主人明确保存的分类，不是模型判断或身份识别；工作结果描述不是任务成功证据。
- **按用途自动装配：**每条可选择日常交流、工作协助、两者或只保存。没有显式用途的请求，无项目为日常，带当前或联合项目为工作；仍与项目范围、provider 许可、有效期及来源状态取交集，允许一个用途不扩大其他范围。共用只引用同一事实 ID，不复制一份正文。虚构角色当前只能保存，不进入这两种现实对话。
- **有效期与纠正：**临时状态必须填写到期时间，其余类型可选；到期只退出自动使用，不删除原件。每次构建上下文、复用快照和引用历史都重新检查当前事实。更改分类递增原修订并抑制旧来源候选，但单独改用途/有效期不解除原来源依赖；来源失效仍暂停使用。
- **兼容原数据：**旧事实及未提供分类的明确指令、0.1.60 以前的规则候选显示“未分类”，保留原项目/provider 行为，不猜测它属于哪种生活或工作信息。面板新建默认个人事实、仅日常/本地；0.1.60 新规则事实默认个人偏好、主人主体、仅日常/本地并可核对修改。已有条目可以逐条整理。已分类条目由旧编辑器或聊天指令修改时保留分类，不能通过漏传字段抹掉限制。

**范围边界：**这里筛选的是长期事实及带其修订引用的派生历史，不是全会话的隐私清洗。当前输入、未标注历史、附件、人格设置、接续和项目原文仍沿原有规则；切到“工作协助”不保证整段聊天只含工作信息。两种用途都面向主人，不能当作对外发送/朗读受众授权。尚无按收件人独立生成、自动画像、多来源投影图、跨节点撤回或稳定联系人实体 ID；未实现的 external/NPC 用途被接口拒绝，不悄悄套用普通聊天规则。完整目标仍按下列各节实施。

<a id="memory-domain-catalog"></a>
#### 个人、工作与共同使用的信息分别保存什么

以下是逻辑用途，不要求每行建立一个数据库、模型或常驻 Agent。长期事实保存在原 MemoryStore，原件、执行状态、配置和技能保持各自权威；物理落点归[存储分层](#section-c30fc1f84bda)。

| 信息类别 | 应保存的内容及权威 | 默认使用与共享方式 |
|---|---|---|
| 主人明确资料 | 主人选择提供的称呼、语言、时区、长期目标；逐项事实和来源 | 相关个人交流可用；仅明确适用工作的字段进入工作视图。地址等私人字段不因属于“主人资料”就全局装配 |
| 喜好与条件偏好 | 兴趣、饮食、表达习惯，以及“工作汇报先给结论”“技术教程要详细”等适用条件 | 通用表达偏好可供多个项目使用；情境例外与全局偏好并存，不互相覆盖 |
| 主人画像视图 | 由当前有效事实组成的兴趣、目标、沟通方式等分项摘要；本身是可重建视图 | 不维护一个由模型不断整体重写的巨大人格档案；明确事实、观察和推测分开，工作视图只取相关字段 |
| 私人交流与共同经历 | 有价值的生活经历、重要约定、共同讨论、关系模式中的偏好及原文 | 个人陪伴按相关性回忆；不默认写入工作报告、代码注释或共享 Wiki。情感价值也可成为保留理由 |
| 临时感受与当前状态 | 主人当下表达的疲惫、心情、临时日程、一次性意愿 | 绑定时间和会话/情境；失效后不继续影响当前画像。一次挫折不推导为长期能力或性格标签 |
| 工作习惯与能力证据 | 主人明确的工作偏好、已验证技能使用经验、适用场景和限制 | 可跨项目的习惯进入获准共用背景；某项目的栈选择不等于主人永远偏爱该技术，一次成功也不等于普遍熟练 |
| 项目资料与决策 | 需求、文档、源码事实、参与角色、约束、决策及适用分支/版本 | 归指定项目/组织域；项目 A 的决定不成为 B 的规则，不自动推导为主人个人观点 |
| 工作结果与实际状态 | 产物、测试结果、执行回执、失败原因；当前状态以任务账本和版本化产物为准 | 记忆只保存摘要和稳定引用。助手说“已完成”不是执行证明；主人转述的结果记录为转述，不伪装工具核验 |
| 可复用经验与公共知识 | 有来源、适用前提、失败边界的通用方法；公开资料与项目抽象经验区分来源 | 原本已公开的知识按其适用范围使用；项目经验通过下节的晋升流程后再跨项目用，不把脱敏摘要自动当作公开知识 |
| 项目与未结事项目录 | 获准项目的 ID、简述、来源入口；个人约定和工作任务的索引/状态引用 | 帮主人统筹生活与工作；详细证据按需读取，目录名称本身也受可见范围限制，不用全库正文填充上下文 |
| 联系人与其他主体 | 区分主人、同事、客户、组织、设备、Agent 的稳定身份、关系与陈述来源 | 同名不同主体不自动合并；客户说“我喜欢红色”不写入主人画像，组织规范不自动变成个人偏好 |
| Jarvis 人格与 NPC 世界 | Jarvis 的表达/关系配置独立版本；NPC 事件绑定 world/persona/角色身份 | 表达人格可共享允许的现实背景；虚构世界不写入主人现实事实。学到的通用方法仍需去除虚构事实、验证后晋升 |
| 环境与凭据 | 环境能力有时效，行动前重新检查；密钥/令牌保存在专用凭据配置 | 普通记忆最多记录受控引用，不将密钥正文建立向量或 Wiki；设备信息不因曾经可用就代表现在可操作 |

<a id="memory-profile-governance"></a>
#### 画像由可纠正事实组成，偏好按情境生效

画像采用“逐条事实集合 + 小而有界的当前摘要”，同时保留来源与适用条件。这样的取舍兼顾局部纠正与阅读便利；整体画像和记忆集合的不同更新代价见 [S232](references.md#s232)。删除某条事实后，相关画像片段需要失效或重建，不能让旧画像继续携带已忘记的信息。

主人明确说“我喜欢简洁”可以成为偏好；模型观察到主人经常要求缩短回答，可以形成可见的待核对建议，不能直接写成“主人不喜欢深入思考”。主人的原话是其表达的证据，对外部世界的陈述仍应区分报告、假设和独立核验。人格配置不会因一条被检索出的笔记而改写。

在满足授权和数据使用范围之后，表达偏好按“本轮明确要求 → 当前情境/项目专属偏好 → 通用偏好 → 默认值”选择。这个次序不允许放宽隐私或执行权限，也不用于裁决事实真伪。两个等效范围内的新陈述互相冲突时保留待核对状态；不能只按设备时钟或模型自报置信度选一个覆盖。

临时状态要有有效期或复核条件，过期退出当前视图；它若作为一段重要经历被保留，仍然是“当时的状态”，不升级为现在的永久属性。兴趣变化、目标完成和工作栈迁移都保留有效时间与获知时间。日常 UI 应允许纠正单项、改变适用范围和停止某类自动提取，不能要求主人编辑一份复杂 JSON 才能管理画像。

<a id="memory-sharing-bridges"></a>
#### 共用信息通过引用、条件偏好和经验晋升连接

| 连接方式 | 例子 | 保存和撤回规则 |
|---|---|---|
| 同一有效事实的受控引用 | “对我的汇报先给结论”适用于多个项目 | 保存一条带条件的偏好，视图引用其 ID/修订；纠正一次即使相关视图失效，不为每个项目复制一条独立正文 |
| 本次联合查询 | 对照 A/B 两个项目的登录方案 | 创建本次允许范围的联合视图，分别给来源；查询结束不改变两个项目的长期分享配置 |
| 从项目识别个人偏好 | 在 A 中说“以后所有项目的汇报都先给结论” | 提出主人通用偏好候选，按已配置策略或明确要求生效；“这个报告用表格”只对当前范围成立 |
| 从工作抽象可复用经验 | 从一次故障中总结“带请求 ID 的幂等重试方法” | 新建有来源的经验候选，去掉项目专有数据并验证适用前提；扩大使用范围需有可检查的既有分享规则或明确决定，不能仅凭模型说“已脱敏” |
| 为当前用途生成最小必要信息 | 私人原因提示今天应简洁交流 | 工作阶段可获得已允许的“先给结论”表达设置，不获得背后的私人原因；此派生设置仍带有效期、来源依赖和用途限制 |

“共用”是允许的读取或经过核对的晋升，不是把所有内容搬到一个 public 文件夹。衍生摘要、画像、经验、关系边和检索缓存默认继承全部输入的限制；多来源组合取共同允许的用途/目的地，不能因其中一个来源公开就公开全部。通过显式晋升形成更宽范围的派生结果时，记录依据、准许的输出字段、审核状态和原依赖；原件不随之公开。原依赖被纠正或撤销后重新核对派生结果，不能丢掉来源以规避撤回。

<a id="memory-use-boundary"></a>
#### 允许理解、允许输出、允许外部处理分别判断

分类标签不是权限。应用在检索前固定主体/项目/世界、用途、消费者及实际目的地，限制候选集合；返回前复核来源、修订、时间、撤销和策略版本。模型只能建议相关资料，不能扩大范围。上游 metadata 过滤仍需按实际后端验证，不能假定更换后端后含义完全相同，[Mem0 的官方说明 S233](references.md#s233)明确列出了差异。

| 当前活动 | 可以装配的内容 | 不应默认装配或输出的内容 |
|---|---|---|
| 私人聊天、陪伴和共同回忆 | 相关主人背景、经历、当前约定；问及工作时可读获准的工作摘要 | 全部项目源码、无关客户资料、其他 NPC 的秘密记忆 |
| 向主人解释当前工作 | 适用表达偏好、当前项目证据、已晋升经验、真实任务状态 | 私人聊天全文、与解释无关的生活细节、其他未选项目内容 |
| 生成客户邮件、共享文档或公开成果 | 此输出用途获准的项目片段、公开知识、可复用经验，以及可披露的格式要求 | 仅供私人交流的背景、内部失败分析、未获准跨项目材料、内部记忆引用中的敏感路径 |
| 跨项目统筹与比较 | 获准目录和明确项目集合的相关证据，各自保留来源 | 将本次读取资格变成永久互通，或把某个客户的观点归给主人 |
| 多 Agent 分工 | 每个任务需要的最小资料和返回产物约束 | 给所有 Agent 完整画像/聊天/钥匙；把 Agent 的猜测写成主人事实 |
| NPC 或角色扮演 | 对应世界状态、允许的设定；角色可见子集 | 将虚构情节变成现实经历，或让 NPC 自动读取主人的私人关系资料 |

**重要实现边界：**若同一个生成请求已经拿到私人原因，只在提示里说“不要写出来”不足以证明其不会出现在交付物中。面向他人或公开的产物阶段应从允许输出的资料重新装配上下文，必要时使用独立调用；不能沿用含私人信息的完整聊天历史、草稿或 Agent 中间结果。无法可靠分离的混合片段先缩小到核对过的字段/句子，仍不确定时不给该阶段使用。额外调用的费用与延迟需计入验收；并非每次私人聊天都要求双调用。

模型提供商、远端 Agent/工具、同步设备、产物读者、屏幕/朗读/通知是不同目的地。允许某模型辅助私人交流，不自动允许公开发布这些内容；允许同步到自己的手机，也不自动允许手机上的云模型处理。更换接入方或输出受众时重新生成视图。原文不适用的出站查询、embedding 文本、缓存、日志和错误报告同样不能夹带原文，读权限和查询词本身都需要检查。

隔离由应用查询与实际上下文构造执行。普通项目先逻辑分域，敏感资料可选独立库/目录、密钥与进程访问边界；逻辑分域并不阻止同用户恶意进程读盘。工程字段归[视图契约](contracts.md#memory-view-contract)，实际执行隔离归[运行边界](security-sovereignty.md#worker-isolation)。用户已明确允许的范围不逐次重复询问，只有用途、受众或范围不清且会影响结果时再澄清。

<a id="memory-human-continuity"></a>
### 人性化连续性与记忆可信度

本节是[伙伴核心](product-requirements.md#personal-companion-core)的数据落点，完整流程仍为 proposed。当前归档、明确事实面板与[完整显式聊天指令](interaction-persona.md#personal-core-ui)已实现，0.1.40 新增下节的明确接续记录，0.1.43 增加[按需中文候选整理](#personal-candidates-runtime)；一般描述的自动理解与完整跨会话相关经历召回仍未实现。下述完整规则属于目标，不扩大局部实现范围。

一次对话按主人身份和当前场景选取：生效的称呼/表达偏好、相关事实或共同经历、当前话题的接续摘要、真实未结事项引用。没有相关记录时使用普通对话，不整库加载历史；项目资料只在相关且范围允许时加入。经历可有叙事价值而没有工程产物，但必须保留说话者、时间、来源、纠正和删除关系；短暂情绪只用于适当的当前回应，不直接推断长期人格。

长期记忆依据未来价值、稳定性、明确意图和可验证来源筛选，不是“模型说重要就永远保存”。问候、重复措辞、短暂情绪、未验证推断和大段生成回答不自动升级为稳定个人事实；可在会话归档中保留其原始上下文。明确“记住”和“忘记”直接进入对应确定性流程，隐含偏好可先作为有期限的候选，重复证据提高可用性但不授予权限。完整晋升规则沿用[选择性记忆](#selective-memory-policy)。

每条记忆区分**说话者、来源类型、可信程度和适用范围**。模型说“文件已保存”只是模型陈述，只有相应工具成功回执才能支持“文件实际写入”的事实；外部网页和其他 Agent 的结论不能自动变成主人指令。多个模型重复引用同一个来源不算独立证据。主人纠正后保留可解释修订，不用累积旧摘要制造相互矛盾的“人格”。

界面应在需要时显示“记住了哪一项、用于哪些范围”，允许更正、撤回和暂停记忆；不在每条回答下要求手工保存。展示“本机已保存 / 已提取 / 待同步 / 存在冲突”而非一个含混的成功标记。尚未做完的工作以真实任务状态回答，不因伙伴人格而虚构共同经历、持续关注或已完成的动作。

自然语言记忆写入需先区分主人陈述、引用、假设和模拟台词，再交给既有记忆 API；候选推断不能直接覆盖明确事实。人格配置只引用适用记忆，模型缓存和检索摘要均不是事实权威。切换模型、重启或更换界面后从持久状态重建；遗忘与修订使相关派生摘要失效，跨设备传播沿用共同体语义。具体场景统一在[V-PAL](delivery-validation.md#personal-companion-validation)验收，不用检索条数替代相处质量。

<a id="continuity-runtime"></a>
#### 明确接续记录的运行语义（0.1.40）

**implemented；局部 verified 见[接续证据](delivery-validation.md#continuity-evidence)。** [continuity.py](../runtime/node-host/jarvis_core/continuity.py)维护独立 `continuity.db`，保存主人明确输入的标题、进展、下一步与状态。它是话题接续，不替代事实库、原会话或 Task Runtime；`open` 表示待续，`owner_completed` 只表示主人标记完成，不是工具执行成功。记录是主人陈述，模型仍需区分陈述和已验证事实。

显式命令的来源固定为原会话中本轮完整的主人控制消息；0.1.43 另接受[经本人确认的普通消息候选](#personal-candidates-runtime)。保存/更新时校验说话者、相应来源标志、内容完全一致与项目相同，保留消息索引、内容摘要、归档修订和记录时间。后续普通消息追加不会使原来源失效；该条消息变更、会话删除或项目改绑后，旧记录不进入模型视图，需重新明确记录。来源只证明说过这段话，不独立证明进展真实，也不自动推导其他消息的含义。

每轮仅核验本会话明确选中的记录。无项目记录只用于无项目会话；项目记录只用于同一项目，不继承到其他项目，也不随跨项目资料联合查询扩域。逐接入方许可先于来源读取判断，每次自动路由候选重新核验；临时模式、关闭记忆或取消选择均不装配记录。只发送记录内容及来源元数据，不发送来源会话全文。

官方客户端给使用接续的回答保存 `id/revision` 依赖，并传递给后续轮次；0.1.42 的关联执行观察另带[状态摘要](#work-continuity-runtime)。更新、遗忘、撤销许可、来源变化或切换范围后，含失效依赖的整轮历史被排除；保留的派生轮次继续携带依赖。旧个人控制消息和本地查询结果不进入模型历史。这里依据保存的依赖关系，不是对任意文本进行语义溯源：主人重新手写/粘贴相同内容会形成新的输入；事实库与接续之间尚无自动依赖推导。

忘记清正文并保留无正文 ID 墓碑、修订和操作回执；不删除原会话、导出、备份或已外发副本。校验形成请求装配时的快照，已发出的请求无法撤回；同一轮装配期间的并发变更不承诺跨数据库线性一致性，下轮重新读取。没有语义向量库、模型提取、后台扫描或定时唤醒；容量与读取预算归[接续契约](contracts.md#continuity-contract)，操作归[接续面板](interaction-persona.md#continuity-ui)。

<a id="work-continuity-runtime"></a>
#### 接续中的真实任务状态（0.1.42）

**implemented；分项证据见[本轮验证](delivery-validation.md#work-continuity-evidence)。** [work_state.py](../runtime/node-host/jarvis_core/work_state.py)是原任务和成长账本的只读视图，没有新执行器、存储、巡检或恢复线程。主人可给一条接续明确关联已有目录/原生技能报告任务、会话需求成长单；关联不会启动、重试、取消或改变其执行状态，也不自动改写主人记录的进展、下一步和完成标记。

每轮只对已选且当前范围、接入方许可及原消息来源有效的接续读取关联。先核对关联对象原会话仍存在、项目归属相同，再核对账本内的会话绑定；记录缺失、会话删除/移组、未知类型、库不可读或产物不可核验统一形成 `unavailable` 观察，不能沿用旧成功结论。不从全部项目自动收集任务；未选用、关闭记忆或临时会话不读取关联状态。

观察明确区分 pending（待办）、running（执行中）、completed（已完成且交付核验通过）、failed、cancelled、unknown、interrupted、unavailable。普通任务须同时为成功、动作确认并通过现有产物摘要核对；成长单须为成功且输出摘要和受控配方期望值再次一致，才显示 completed。产物完整性不等于模型报告中的推断必然正确；也不把“一个任务完成”解释为“整个话题完成”。

模型获得的是宿主本次核对的 `linked_work`，与主人原文进展分别标明。只包含标识、状态、核验结果、结果摘要和有界机器错误代码，不包含产物正文、文件清单、路径、调用凭据或原始错误消息。状态结论优先于旧进展中对该任务的陈述；主人的目标和下一步仍保留。选用继续话题本身不构成重试授权，失败或未知须回到原任务/成长入口核对。

持久接续只保存对象引用，实际状态在请求时读取。回答除接续修订外还记录关联观察的 `work_digest`；它涵盖状态、错误与核验结果，观察时间不参与摘要。状态变化、产物损坏或记录不可用时，旧摘要不匹配，该状态派生的整轮历史退出下次装配；解除关联也使原依赖失效。读取只形成当轮快照，不承诺跨账本线性一致或已派发请求实时撤回。

同轮来源归档缓存复用，最多读取已选记录的有界关联；管理总列表不读取全部任务或产物。权限继续使用该接续已有的接入方许可，界面在保存关联前说明这一点。关联、解除、忘记接续均不删除任务账本或交付；字段、读取上限与旧版本兼容归[关联契约](contracts.md#work-continuity-contract)。

<a id="personal-candidates-runtime"></a>
#### 常见自然表达的候选整理（0.1.43）

**implemented；局部验证见[本轮证据](delivery-validation.md#recovery-candidates-evidence)。** 独立的 [personal_candidates.py](../runtime/node-host/jarvis_core/personal_candidates.py) 从一条已归档的本人普通消息提出事实或未结事项候选，复用 MemoryStore / ContinuityStore；没有新数据库、提取模型、后台扫描、提醒器或第三方依赖。它是按需、可编辑的中文规则入口，不是通用语义理解或自动经历召回。

目前识别“我更喜欢简洁回答”“以后叫我老王”“我们下次继续讨论学习计划”“我还没完成读书笔记”等常见句式。包含引用、假设、示例、模拟台词、代码、明显凭据词或不保存要求时整条不提取；遗漏和误匹配仍可能发生，因此必须展示原句和候选供核对。模型回答、附件、未保存消息、控制消息和临时会话不能作为候选来源。一般聊天不自动晋升为事实，也不因未匹配而禁止正常交流。

**0.1.52 收紧事实资格：**含问号/句末疑问词，以及“这一次、今天、暂时”等明确短期词的规则事实不再提出；未结事项匹配保持原规则。稳定偏好与单次例外写在同一句时也保守跳过，避免凭规则猜测保留哪一半，可改用语义整理。这会减少误记，也会增加部分漏记；具体对照见[固定样例结果](delivery-validation.md#memory-extraction-pilot-evidence)。

**0.1.60 统一事实核对：**规则事实进入与语义事实相同的本机比较、显式沿用/更新和原存储事务；显示原句、分类与用途，保存前核对已纠正/遗忘水位。旧预览不能新增事实，旧精确回执仍可查询；冻结的 v1 候选身份不变，不能借切换提取器绕开来源撤销。未结事项仍走原独立入口。完整字段与兼容规则只维护于[候选契约](contracts.md#personal-candidates-contract)，实测与部署范围见[入口一致性证据](delivery-validation.md#rule-memory-review-evidence)。这一步不扩大中文规则语法或把词项相关当语义等价。

预览无持久写入；主人可改标题、内容、下一步或忽略，确认后才通过原存储提交。事实在项目内默认留在当前项目，可明确选择通用个人记忆；未结事项始终留在来源项目/普通会话范围。新记录默认仅本地使用，云接入方许可仍由原记忆面板设置；候选未结事项不是执行任务或定时提醒，也不自称已完成。

确认时重新核对来源摘要与范围。候选接续额外保存“本人确认的普通消息来源”标志，后续按同一消息索引、内容摘要、角色和普通消息标志复核；来源变更或删除使其不再进入模型视图。0.1.43 的事实仅记录本人确认类型；0.1.44 新事实补充下节的来源与撤销能力，旧记录不自动推断来源。

同一确认使用由来源、内容及范围派生的稳定回执，网络响应丢失后重复提交不会复制记录；遗忘后重送同一确认不会复活内容。不同内容、不同范围是新的请求，0.1.44 的事实还必须通过下节的来源撤销检查；不自动覆盖同名不同值。遗忘清理的是对应长期记录和已追踪的派生上下文，**不会删除原普通聊天句子**；当前会话历史仍可能携带原句，需要时另行删除源会话。这也不能撤回已经外发的内容。字段、容量和兼容性归[候选接口](contracts.md#personal-candidates-contract)。

<a id="retrieval-ranking-module"></a>
#### K5：可替换的检索排序模块（0.1.79）

**0.1.79 已实现模型生成受限源码、独立评估、持久试用/保留/回退；实测范围见[K5 模块证据](delivery-validation.md#k5-ranking-module-evidence)。** `knowledge.py` 实际检索路径把排序委托给独立 `retrieval_ranking.py`：先由宿主完成来源授权、实时摘要、切块和词法候选资格，再把不可修改的标量候选交给排序器。接口 v1 只接受完整候选索引排列；增加/遗漏/重复来源、越界索引、修改输入或协议不兼容会返回原 `lexical-v1` 结果。项目均衡、引用编号、原文和上下文预算仍由宿主负责。

无已确认选择时保留原词法排序。0.1.78 的开发候选 `coverage-v2` 仍只用于既有对照，不冒充模型生成成果。0.1.79 的 `ranking_program.py` 定义有限语言：模型只能排列不同的负向数值特征（词覆盖、正文覆盖、标题覆盖、原分数），必须保留原分数及路径/行号稳定尾序。宿主逐棵比较完整 Python AST 与规范生成树，拒绝其他语句、调用、表达式和默认参数；验证后只解释有限的特征键元组，绝不在主进程执行或导入候选 Python。原始 Python 仅在既有 LPAC 中独立运行，与解释器结果逐项比较。

这个选择避免每次检索启动隔离进程，也限制可演化范围：目前不能自行新增任意算法、依赖、向量库或网络请求。仍使用原来最多 2048 块/128 个查询词；按需读取已保存选择，不缓存旧来源正文。没有新增数据库服务、常驻 Worker 或第三方包；持久状态扩展原成长 SQLite。排序本身不调用模型，只有显式生成候选才请求一次模型。生命周期、配额与恢复只维护于[检索模块成长](evolution-release.md#ranking-module-growth)，HTTP 和数据字段归[契约](contracts.md#ranking-module-contract)。

排序更相关不自动意味着最终回答更好：上下文可容纳全部资料时可能没有收益；候选在同义改写、词义歧义和资料时效冲突上仍可能失败。独立检索集和真实模型回答对照分开记录，保留失败，不把有限词法模块称为通用语义记忆或无限自主重构。

#### 按需语义事实候选（0.1.50）

**implemented；局部验证见[语义候选证据](delivery-validation.md#semantic-candidates-evidence)。** [semantic_candidates.py](../runtime/node-host/jarvis_core/semantic_candidates.py)是最小结构化 LLM 提取基线，复用原模型网关、事实存储、分类和来源检查。它与上节的确定性规则并存；没有引入 LangMem/Mem0 依赖、向量服务、常驻模型、提取扫描器或新数据库。普通聊天、打开规则预览和读取记忆不因此增加模型调用；只有主人点击语义整理才调用所选具体模型。

处理对象是一条已归档的普通本人文字，整条消息发往明确显示的供应商；不附带其他记忆、历史、人格、技能、附件或项目文件。默认不跨供应商回退。输入中的明确不保存要求和常见凭据特征先做本机拦截，但不宣称是通用秘密识别器。模型可以提出主人偏好/事实/经历、项目事实/结果、他人和虚构角色候选，不能决定事实真伪、执行成功或授权范围。提取出的正文、主体、用途和原句都交给主人核对；不自动建设或重写画像。

**0.1.52 纠错增量：**“研究密码学”本身不再触发语义提取的密码拦截，同句另有密码字段或凭据仍拦截。提取规则明确：第一人称角色扮演属于虚构角色；未执行计划进入未结事项而非长期事实；没有项目范围就省略项目断言，不能换成主人事实。宿主对“我扮演…”、“我明天打算测试…”、“这个项目确定使用…”等有限明确标记额外拒绝错误类别，整批不签发预览。这是针对实测错误的保守检查，不是完整的语义分类器；复杂转述、其他语言和同句混合主体仍可能漏检或被保守拒绝。它不会自动把被拒内容写进未结事项，也不提升任何任务的执行状态。

主人信息默认用于日常聊天，项目信息默认用于工作，他人和虚构资料默认只保存；主人可以编辑分类、主体名称及日常/工作用途。虚构资料仍禁止用于现实记忆，项目类型必须绑定项目。保存后继续默认仅本地模型可用；本次明确将原文送往云端提取，**不等于授权以后把保存的事实发往该云端**。事实内容和用途在原 MemoryStore 的同一事务提交，不先写入宽泛记录再补权限。

原句由宿主确定性分句并回显，不相信模型生成的引文。每句最多一个候选，避免模型换标题或改写正文就产生新身份；能对应已有规则事实时沿用该规则候选身份。0.1.52 将旧身份语法保留在 `identity_candidates_v1`，与新候选资格过滤分开；升级过滤规则不能顺便更换旧标识、绕过遗忘。该兼容函数继续参与实际来源校验，并非待清理的废弃实现。其余句子身份取同一来源消息中的句位。纠正、用途修改或遗忘后，同一身份不能经另一份模型措辞重新保存；精确确认重试只返回原回执。这是保守的句级防重复，可能把同句不同事实一并阻止，需要主人用明确指令重新记录；**不是跨消息、任意改写、重新粘贴后的语义遗忘匹配**。

预览由当前宿主签名，短时有效，只在请求和页面内存中存在。确认重新检查签名、候选身份、原消息摘要、来源资格和范围；过期或宿主重启需重新整理。没有确认就不写入事实，模型返回不完整、来源变化、取消或格式失败都不提交、不自动重发。模型请求与聊天共享并发槽位、停止控制和用量记录；超时请求保留槽位直到实际 worker 退出。边界和字段只在[接口契约](contracts.md#semantic-candidates-contract)维护。

2026-10-18 增加语义候选的修订屏障：主人纠正或忘记记忆后，已在处理或尚未确认的旧语义预览不能迟到写入，另一段聊天的预览也需重新整理。新增事实和确认回执重试仍可正常处理。完整触发、事务与兼容边界只在[接口契约](contracts.md#semantic-candidates-contract)维护；12 组公开多轮回放及界面证据见[本轮验证](delivery-validation.md#memory-lifecycle-evidence)。这不替代后续的语义合并和新来源同义遗忘判断。

2026-10-19 工作树增量已实现[本机重复与差异核对](contracts.md#memory-candidate-review-contract)：语义候选保存前可比较同范围、同主体的旧记录，提示重复表达、可能补充或偏好变化，再由主人沿用、更新或另存。旧事实不发送给模型；自动更新画像仍未启用。更新复用既有 ID、权限和来源撤销机制，不增加另一份事实库；限定猜测纠错检查也已补入，避免把“你猜错了，我没有提供住址”直接变成负向住址画像。临时核心、UI 和资源验证见[本轮证据](delivery-validation.md#memory-candidate-review-evidence)，正式发布状态以该处为准。

当前仅扩展事实候选；未结事项继续走规则入口。自动批量提取、通用语义冲突裁决、自动去重合并、跨句细粒度事实、短期状态自动到期推断、画像派生、完整外部受众隔离及多节点复制仍未实现。规则与最小 LLM 已建立[30 条公开先导样例](delivery-validation.md#memory-extraction-pilot-evidence)，另已完成 [LangMem](delivery-validation.md#memory-langmem-shadow-evidence)与 [Mem0](delivery-validation.md#memory-mem0-shadow-evidence)公开样例影子对照；独立留出与完整框架准入仍按[选型验收](delivery-validation.md#memory-selection-evaluation)，不能用先导结果宣布框架胜负。

| 原消息仍有效 | 事实可按原范围和接入方许可使用；本机面板可查看原文。模型只接收选中的事实，不因查看来源而收到整条原消息 |
| 仅追加聊天、会话改标题 | 原消息定位及摘要未变，事实保持可用 |
| 原消息改动/删除、角色或来源项目变化 | 候选事实保留在面板，但暂停进入模型上下文；相关旧事实引用历史也退出装配。不会静默删除主人的记录 |
| 来源读取超出本次预算 | 标记未完成核对并暂停使用，主人可刷新或核对；不将未检查视作有效 |
| 主人修改事实内容、标题、范围，或点击“确认独立保留” | 形成新修订，不再以原消息可用为前提；保留来源定位，旧候选不能覆盖。只调整云接入方许可不会解除来源依赖 |
| 主人忘记事实 | 清空事实正文及其原文定位，只留下有界去重/撤销元数据；同一个来源候选改名、改预览内容或切换保存范围不能重新创建它 |

稳定来源标识与请求回执分开：原确认响应丢失可重试，不重复写入；同一来源同一范围改预览内容时要求修改已有事实。不同来源试图复用一个已有候选事实的名称时，要求在面板核对，不静默更换其主来源。与已有独立明确事实完全相同的候选可指向该事实，但不会使独立事实依赖聊天存在。

纠正或遗忘后，受撤销的来源候选不能通过选择另一范围再创建副本；已明确保存到其他范围的另一条现存事实不会因此被删除。主人仍可通过明确“记住”指令建立新的决定，撤销记录不阻止本人重新决定。当前标识只覆盖本机同一消息位置及同一原始规则候选，不声称识别跨消息转述、复制到新会话、任意新算法语义等价或多节点旧副本。

旧 v1 记录保持既有明确事实语义，不从归档猜造来源；历史上已经忘记、且从未保存来源标识的候选无法追溯封锁其所有变体。未结事项继续使用 0.1.43 的来源与精确请求回执，本节增强的改名撤销限于候选事实。跨库读取并非原子快照，已派发模型请求不能撤回；读取后的新变化在后续装配生效。数据库迁移、限额和降级边界只在[运行契约](contracts.md#memory-provenance-contract)维护。

<a id="project-knowledge-compilation"></a>
### 项目知识编纂：来源变化后有界更新

KnowledgeCompiler 将获准源码、现有权威文档与测试回执组织为可检索的事实和解释；OpenWiki 的具体借鉴范围见[源码对照](stack-project-layout.md#openwiki-adoption)。这是知识模块的生产者，不是另一个自动执行核心。

流程为：登记项目与来源范围 → 读取 manifest/目录和来源版本 → 建立 Claim 到源文件/段落/测试的引用 → 生成候选说明 → 检查引用、冲突、状态和文档结构 → 更新对应权威位置或派生阅读视图 → 增量更新索引。源码变更只把依赖它的 Claim 标记为待复核，未受影响内容不重写；哈希未变证明内容相同，不证明解释正确。

以本仓库为例，`docs/manifest.json` 指定主题权威，`implemented/verified` 必须对应实现与测试证据。自动生成的“代码是这样工作的”不能覆盖尚属 proposed 的产品目标，也不能把后者写成已具备能力。生成过程中保留来源版本，发布前发现源文件已改变则重新核对，避免在旧快照上确认新文档。

跨项目链接采用稳定项目/文档/章节 ID，实际本机路径由节点映射；电脑的盘符不能成为手机的全局身份。移动、删除或分支切换触发引用检查，保留提交/分支/工作区版本区别。未保存草稿、未追踪临时调试内容不自动并入正式知识。源码、文档、截图和网络资料分别有受限解析器，按真实需要启用，不为了“全知识”安装全部解析工具。

<a id="section-63a49a4a6d48"></a>
### 写入与查询

写入沿用[知识晋升](#continuous-learning-2)：捕获已获准原件与事件 → 确定性标签/隐私检查 → 可选模型提取候选 → 保留来源的事实修订 → 异步更新派生索引。原始事务提交和可检索状态分开返回；提取超时不丢原件，重复事件不重复生成已晋升记录。断网或资源不足时允许积压提取，明确显示处理水位。

查询先按主人、项目、现实/模拟域、资料权限、当前版本、有效期和撤回状态限定候选，再分别进行词项与向量检索，按稳定文档/事实 ID 合并排序，按需增加重排或时态关系查询。初期可用倒数排名融合，不能直接相加来自不同后端且尺度不一致的相似度。最终上下文仍检查权限和引用，不能先把全部资料发给云模型再要求它过滤。

上下文包带证据引用、事实有效时间、来源节点、查询水位和冲突提示。“同步完成”“索引更新完成”和“事实已解决冲突”是三个状态。只有摘要时先标摘要，必要时打开原件；摘要继承来源的数据外发限制，来源过期/删除后关联摘要失效。中文全文基线的限制见[实际探测](delivery-validation.md#memory-fts-evidence)，避免把零命中解释为系统没有这段记忆。

完整请求通过 MemoryViewResolver 解析当前主人、任务、项目集合、人格/模拟域及实际模型目的地，再调用 Retriever。共享背景采用小而有界的预算；项目目录先发现，详细证据再按章节读入。临时跨项目联合视图用完即释放，不把两个项目自动合并成一个知识库。外部模型回退换供应商时重新判断资料是否允许发送，不能只检查最初的路由。

有害越域候选应在检索候选生成阶段排除，并在输出前再次按 MemoryStore 当前修订核对；不能先全库 top-k 再过滤，导致既漏掉允许结果又暴露受限信息。索引尚未追平时优先返回确定性事实、标注缺口，必要时进行有界原件读取；没有可靠证据时说明不确定，不编造记忆。接口字段见[MemoryView 契约](contracts.md#memory-view-contract)。

<a id="section-2c2fddabd6b3"></a>
### 完整节点如何保有自己的 Jarvis

每个完整节点预装控制所需知识、主人明确偏好及其离线任务依赖的资料子集，保存本地事实与检索入口。仅有远端对象引用而无本地内容时，应显示“资料未离线准备”，不能声称全知识可离线。轻节点可以只缓存部分内容；节点等级和限制由[共同体设计](federation.md#offline-federation-1)说明。

联网后共享的是获准事件和资料，不强制每台设备拥有相同索引、同一模型或全部私人记录。事实一致性由[同步与冲突协议](federation.md#memory-replication)维护；每台节点按自己的计算能力构建检索视图。中心检索不可用时回到本地，并说明查询范围；“联网形成统一 Jarvis”在工程上表示共享身份、可追溯记忆与受协调行动，不是自动消除所有并发分歧。

<a id="section-59821024e11f"></a>
### 可替换接口与自我改进边界

MemoryStore 管理事实/事件和导出；Extractor 只产生带来源的候选；Retriever 返回引用与版本；EmbeddingProvider 管理向量空间；SyncTransport 搬运已获准变更。接口职责见[公共契约](contracts.md#memory-provider-contracts)，不要把某框架私有对象直接存为唯一长期格式。

换模型、索引或提取算法使用独立代次：固定原件和评测集 → 在旁路构建 → 对照查询 → 原子切换索引指针 → 保留可恢复旧代次 → 按引用退役。构建期间的新事件按日志水位补齐；删除/撤回对新旧索引都立即生效于查询门禁，不能等待重建结束才处理。失败时回到兼容代次，绝不回滚主人后续修正或恢复已遗忘内容。

这也给 K5 提供第一个可验证的自我改进对象：只改检索实现，比较证据召回、错误引用、中文短词、时间冲突和资源成本；事实原件、隐私门禁与评估基线保持独立权威。

## 记忆、知识与数据同步



<a id="memory-data-1"></a>
### 数据分层

| 层 | 内容 | 权威性 |
|---|---|---|
| 原始事件 | 用户指令、观察、反馈、动作回执 | 保留原始来源，不代表内容必然真实 |
| 结构化事实 | 偏好、设备、关系、项目事实 | 带证据、范围、时间、置信与冲突 |
| 情景记忆 | 共同经历、任务过程与结果 | 可回溯事件 |
| 程序性记忆 | 已验证技能与使用经验 | 带版本与测试 |
| 工作记忆 | 当前对话和任务上下文 | 短期、可压缩、有检查点 |
| 派生数据 | 摘要、向量、索引、统计 | 可重建，不能成为唯一原件 |

框架检查点用于当前执行连续性，长期资料另行管理；可参考 LangGraph 的 checkpointer/store 区分。[S11](references.md#s11)

<a id="memory-data-2"></a>
### 同步策略

0.1.84 的共享资料可由主人明确选为本轮聊天附件；它是带来源的副本，不是主人事实或自动记忆晋升。原文省略、候选排除、会话隔离及撤回限制统一见[共享副本边界](federation.md#shared-card-copies)。

同步机制、按数据类型的合并规则及冲突处理统一维护于[共同体记忆复制](federation.md#memory-replication)。本页定义哪些资料可以分享与遗忘；共同体页定义它们怎样送达、确认和避免旧副本复活。

<a id="memory-data-3"></a>
### 隐私范围

同步范围与外部模型使用许可分开：

- sync_scope：device_only、selected_nodes、community。
- external_processing：deny、allow_listed_providers。
- 保留级别：临时、长期、到期删除、用户手动保留。
- 数据标签随产物和派生摘要传播；摘要不能绕过原始资料的外发限制。

凭据保存在所属节点的系统密钥存储中，其他节点通过授权代理请求动作；不把密钥混入记忆、提示词和同步事件。

<a id="memory-data-4"></a>
### 本地事务与复制

记忆存储有自己的唯一写入 API 与本地事务，和任务/动作控制账本分别管理；不得直接写其他模块所属表。事件、outbox/inbox 与跨域事务边界统一见[记忆组件契约](contracts.md#memory-provider-contracts)，多机复制、去重和恢复代次见[共同体协议](federation.md#memory-replication)。

关键动作和授权账本在向调用方确认前必须达到规定的持久提交级别；SQLite 同步策略和备份策略分别验证断电与介质故障边界。索引落后允许标注降级，事实提交丢失不能用“最终一致”解释。

<a id="memory-data-5"></a>
### 遗忘与备份

删除请求生成传播记录，删除原始内容及对应摘要、索引和缓存。审计保留最少的删除事实，不保留被删除的敏感正文。备份设保留期，并记录备份中的删除处理规则。

离线设备只能在重新连接后收到删除指令；已被不可信设备复制的内容无法保证远程销毁。安全归档或压缩日志前，应确保快照与同步游标一致，避免旧节点重连使已删除内容复活。

墓碑传播、过期副本与重新入群的具体规则统一见[共同体记忆复制](federation.md#memory-replication)。

<a id="continuous-learning"></a>
## 持续互联网学习与知识库自主重构



<a id="continuous-learning-1"></a>
### 持续学习的目标与边界

系统可以根据主人的长期目标、重复失败、设备变化和技术更新，持续跟踪官方文档、论文、软件发布与获授权的信息源。学习任务具有明确用途、来源范围、预算、周期、截止时间和收益标准；没有新信息或收益时低成本等待。

学习可以改变知识、技能、策略和实现，不能改变服从谁、哪些资料可外发、授权范围、G0 或关停规则。“从网上学到了一个新方法”不自动构成安装程序或扩大权限的许可。

<a id="continuous-learning-2"></a>
### 学习流水线

来自网页的提示、代码注释、附件和工具定义保留不可信来源属性，不能直接作为控制指令。提示注入防御仍存在技术边界，所以需要隔离、权限、执行检查和回归共同发挥作用。[S34](references.md#s34)

<a id="continuous-learning-3"></a>
### 逻辑模块

| 模块 | 责任 |
|---|---|
| learning-planner | 把能力缺口和技术变化转为有预算的学习任务 |
| technology-watch | 监测版本、论文和获授权信息源，去重与筛选 |
| evidence-ingestion | 采集、解析、哈希、来源与版本登记 |
| knowledge-quarantine | 保存未验证资料和待验证代码，不持生产权限 |
| knowledge-validator | 检查事实、冲突、时效性和实验结果 |
| memory-curator | 纠错、合并、过期、删除和经验归档 |
| knowledge-evolution | 提出知识结构、索引、存储与检索方法变更 |
| promotion-controller | 分别检查知识、技能和程序的晋升条件 |
| knowledge-evaluator | 保留查询测试集，检查检索、证据、污染和性能 |

知识晋升与代码发布共用根规则和证据机制，具体门槛不同；不能因为文档核验通过就跳过程序测试。

<a id="continuous-learning-4"></a>
### 知识的三个层次

1. 证据层：原始资料、来源、版本、时间、必要快照和保留规则。
2. 规范知识层：事实、关系、项目记录和操作经验，以及指向证据的链接。
3. 派生检索层：摘要、全文索引、向量、知识图谱和缓存，可重建与替换。

MemGPT 的分层记忆与 MemOS 的记忆资源管理可作为研究参考；它们不保证无限记忆、无误检索或生产迁移自动正确。[S31](references.md#s31)[S32](references.md#s32)

<a id="continuous-learning-5"></a>
### 允许自主重新设计知识库

在既有数据和维护权限内，系统可以比较并改造：

- 数据库、对象存储和冷热分层。
- 文档分块、全文索引、向量索引和缓存。
- 嵌入模型、维度、距离度量和重排模型。
- 实体本体、关系类型、实体合并和知识图谱。
- 全文、向量、图谱和混合检索路径。
- 去重、摘要、归档、过期和删除机制。

GraphRAG 提供可配置的实体、关系、社区摘要与向量索引流水线参考；不要求所有知识都使用图谱，也不能把模型抽取的关系当作已证明事实。[S33](references.md#s33)

<a id="continuous-learning-6"></a>
### 迁移协议

先保留旧读入口，建立新索引/存储，在独立空间回填历史和追赶新增事件，再对照查询、逐命名空间切换，最后清理旧格式。

- 迁移版本固定，读请求绑定一致的数据视图，不混用半完成索引。
- 新旧嵌入空间不能直接混合；记录模型、维度、分词/预处理、分块与索引版本。
- 本体变化保存旧实体到新实体映射与歧义，不覆盖原始证据。
- 重放仅重建知识，不能重执行曾记录的现实动作。
- 墓碑、删除、访问范围与撤销记录同时迁移，防止资料复活或跨域暴露。
- 可回退性需要验证新写入与旧格式兼容；只有旧备份不等于无损回退。
- 当 G0 锁存触发时，停止新迁移工作，持久记录安全中断点；不得以“完成迁移”为由继续自主作业。

<a id="continuous-learning-7"></a>
### 记忆域与可信状态

```text
owner/<id>/preferences
owner/<id>/episodic
project/<id>
shared/verified
research/quarantine
world/<world_id>/<branch_id>/canon
world/<world_id>/<branch_id>/agent/<agent_id>/beliefs
world/<world_id>/<branch_id>/events
```

每条知识携带来源、版本、适用范围、有效期、敏感级别和 truth_status。状态区分直接记录、来源声明、已核验、推断、争议、过期与虚构；反复检索同一推测不会提高它的证据等级。

NPC 记忆不得改写真实用户偏好。模拟中的算法、代码和性能经验若要用于现实任务，须单独验证晋升。

<a id="continuous-learning-8"></a>
### “不断积累”不等于无限堆积

知识量增长必须同步管理去重、版本、过期、删除、引用成本与检索质量。主人要求删除的资料不能以“自主进化需要”为理由保留。

离线时继续整理本地资料、运行已授权实验和重建索引，标记外部事实的最后核验时间。需要网络的学习排队；资源不足时优先暂停学习，保留交互与任务状态。

<a id="system-health-12"></a>
## 知识、技能与规则也会退化

持续学习必须检测过期信息、错误摘要、虚假来源、循环引用和同一错误被多个 Agent 重复强化。原始证据与派生摘要分开；纠错更新事实状态并重建受影响索引，不把重复次数当作真实性。

技能增加后检查相似能力、依赖冲突和替代关系；优先改进既有能力而不是每次失败都生成新工具。退役技能先限制新调用，保留旧任务版本和历史证据。新增技能不能凭说明文本取得新的权限。

规则必须区分不可削弱的根宗旨、主人授权、组织策略与普通偏好。冲突时按固定优先级处理，不能让检索排序决定谁覆盖谁。规则更改需要来源和生效范围；模型主动建议可以保存，但不会自动成为新授权。
