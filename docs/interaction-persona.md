## 个人助手入口：自然交流与按需展开的工作台

**默认进入与 Jarvis 的个人会话，打开即能交流，不要求先选择项目或文件夹。** 以[个人助手与伙伴核心](product-requirements.md#personal-companion-core)为产品依据：持续身份、相关记忆、自然表达和日常协助从文本核心开始；工作时再打开项目、文件、任务与专业工具。用户提供的 Codex 截图用于借鉴布局、缩放和面板组织，不决定 Jarvis 的产品身份。阶段归属统一见[界面实施映射](core-bootstrap.md#workbench-stage-map)。

日常入口保留 Jarvis 品牌和可辨认的待命/回复状态，允许闲聊、共同思考或提出需求。人格称呼、语气与关系模式由主人设置；适时显示一条相关的记忆或既有事项提示，不用任务看板、成长指标和项目列表挤占交流空间。项目工作、设备和成长中心按需展开，关闭面板仍回到同一个助手。这里是目标设计；当前普通聊天可用，0.1.39 已实现[明确记忆与基础交流设置](#personal-core-ui)，0.1.40 增加[明确话题接续](#continuity-ui)；完整经历召回、称呼/声音/形态人格仍待实现。

本节是 **2026-10-15 的 proposed 产品设计**，不是已交付桌面软件。现有 0.1.21 网页已提供聊天及单次停止、模型/推理选择、目录与限定浏览器共用队列，以及[项目文件夹与文本保存子集](core-bootstrap.md#project-workspace-entry)；项目登记持久化；0.1.24 起普通会话文字自动归档，0.1.25 起增加下文明确事实记忆，0.1.26 增加项目文档检索与来源预览。下述个人助手生命周期按 2026-10-16 用户要求 accepted；已增加[模型与费用后台](#model-admin-experience)与[页面配色](#workbench-appearance)；多标签文件工作台、实时语音与完整设置尚未实现。当前使用和运行证据分别见[原型入口](core-bootstrap.md#section-b3e262fa3ec1)与[分版本验收](delivery-validation.md#versioned-evidence)。

<a id="personal-assistant-lifecycle"></a>
### 私人助手的常驻、待命与会话停止

**当前私人电脑使用约定：助手开启后持续可用，没有工作时显示“待命中”；输入区的停止只结束当前会话的本次回复。** 这是 2026-10-16 用户明确修订的产品规则，优先于早期全局停止和恢复认证设计。

- 发送后，发送箭头变为方形“停止生成”；当前回复结束或被停止后恢复发送箭头，可以继续输入。停止不关闭助手，不清空其他会话，也不取消独立后台任务。
- 本页回复时显示“回复中”；其他会话或后台任务仍在执行时显示“运行中”；没有活动时显示“待命中”。连接失败明确显示异常，不能假装待命。
- 任务中心的“取消任务”只针对选中的任务；暂停队列只暂停后续派发。不提供全局停止锁存操作；托盘的“退出 Jarvis”是用户明确关闭当前应用，不把会话取消变成退出或锁存。
- 当前使用不设置恢复密钥、密码、公钥登记或解锁认证。旧版留下的停止数据仅提供[一次性本机兼容迁移](core-bootstrap.md#runtime-control)，不成为日常使用步骤。
- 用户明确退出助手时才结束其运行。关闭网页页签只关闭界面，后台服务继续存在；0.1.18 的 Windows 托盘新增明确退出入口，只结束其绑定的助手实例。有活动时先提示，退出后不再派发并取消当前本机活动；尚未确认的外部效果保留既有 UNKNOWN 语义，不保证已经被远端接纳的模型调用或计费撤回。

托盘的图标、悬浮文字与右键菜单共同表达状态：绿色徽标“待命中”、蓝色“运行中”、黄色“需要处理”、灰色“正在连接/连接中断”。每轮完成后约 2 秒发起下一次本机状态检查，请求超时 1.5 秒；只接受启动时绑定的实例标识。连接失败或端口被另一实例接管时不显示待命，恢复后更新。助手异常退出时托盘留下断连提示，可明确关闭图标；正常退出后移除图标。双击和“打开 Jarvis”使用默认浏览器；不另建第二套工作台。启动方式见[托盘入口](core-bootstrap.md#windows-tray-entry)，验证见[本轮证据](delivery-validation.md#tray-evidence)。

待命意味着服务进程仍可接受请求，不意味着一直调用模型、计费或自行创建任务。本轮不安装开机启动、守护服务或定时任务，也不承诺关机、休眠或进程崩溃期间仍在线。生命周期与两会话取消隔离的实现证据见[0.1.14 验证](delivery-validation.md#personal-lifecycle-evidence)。

### 布局、页面与视觉尺度

工作台与设置页的运行版本统一显示在页面右下角，采用 `v0.1.26` 这样的简写，读取实际运行版本；左侧栏不再放版本号或“本机运行”前缀。版本文本不接受点击，底部预留空间，避免挤占输入操作。

默认是安静的浅色工作台，延续现有深蓝 J 标识；新会话保留充足留白，开始工作后再按内容展开面板。以下尺度是 Jarvis 的设计值，不是对截图的像素测量。

| 区域及相对位置 | 常驻内容 | 展开后的内容与行为 |
|---|---|---|
| 顶部窗口/菜单条 | 返回、前进、文件、编辑、视图、帮助；桌面壳提供系统窗口按钮 | 文件含打开文件夹/文件与最近项目；编辑含撤销、复制、查找；视图控制侧栏、工作面板、缩放和主题；帮助显示快捷键、版本及诊断 |
| 会话顶栏右侧工具区 | 记忆、设置等工具图标 | 入口顺序、提示与左栏使用规则见[设置中心](#workbench-settings) |
| 会话导航侧栏，默认 260px，可调 220—360px | 新会话、搜索、固定项、最近会话；项目作为可展开分组 | 保留打开文件夹和项目组织能力；没有项目时不显示空项目树；运行、等待、需处理、未读用图形加文字提示；侧栏可折叠 |
| 中央上方，约 56px | 会话标题、助手状态和工作面板开关；有项目/任务时才显示对应位置与活动 | 路径可复制；远端同时显示设备名；改名、归档、导出在会话菜单中 |
| 中央会话区 | 新会话问候“想聊点什么，或者有什么需要我帮忙？”；按已设人格调整表达 | 普通聊天不强制计划、执行摘要或文件；有实际任务时展示进度、来源和产物；欢迎页不挤占输入空间 |
| 中央底部输入区，最大宽度 880px | 上下文条、正文、附件条、工具栏、状态提示 | 与会话同一轴线；正文随输入增高到约 240px 后内滚动；不遮住最后一条消息 |
| 右侧工作面板，默认关闭 | 打开时为文件/预览/差异/浏览器/任务详情标签 | 默认约可用宽度的 40%，可拖动或全屏；切换会话按会话保存标签与滚动位置 |
| 底部辅助面板，默认关闭 | 日志、执行输出；具备能力后显示终端 | 会话仍可输入；关闭面板只隐藏视图，任务生命周期见任务章 |
| 全局状态区 | 服务连接、离线/联网、需处理提示、停止入口 | 断联展示最后更新时间；不能把最后一次正常状态继续显示为实时健康 |

基础色沿用现有 `#16283B` 深蓝、`#315E91` 强调色、`#F3F5F7` 侧栏、`#FFFFFF` 内容面；正文建议 14—16px，Segoe UI / Microsoft YaHei，代码用系统等宽字体；4/8px 间距体系，菜单圆角 8—12px，输入框 16—18px。深色主题单独配置可读文本和边界；警告/错误不只靠颜色。按钮点击区域以不小于 32px 为桌面目标，触屏重要按钮以 44px 为目标，焦点始终可见。图标规范见[Jarvis 标识](#jarvis-brand-icon)。

<a id="workspace-folder-flow"></a>
### 新会话、打开文件夹与项目连续性

**个人会话是默认交流空间，不是一个虚构的工程项目；“项目”组织选定资料和相关会话，“任务”记录被接纳的工作，“工作目录”指定文件操作位置。** 主人通用偏好不属于某一个项目。一个项目可以有多个会话，一个会话可以引用多个任务；切换页面不等于取消任务。文件夹中的文本是上下文材料，其指令可信范围由[授权规则](security-sovereignty.md#identity-authorization)约束。

1. 从“新会话”、`Ctrl+N` 或项目菜单“在此新建会话”进入。全局新会话默认个人交流，无需操作“无项目”选项；项目内新会话预选该项目并明确显示目录和电脑，不悄悄继承上一个无关项目。
2. 点击“打开文件夹”或 `Ctrl+O`。0.1.74 可输入新目录的完整路径并点击“创建并打开”，上级目录须已存在；已有目录只打开，不覆盖其中内容。浏览器和桌面均通过本机后端执行，不要求只在桌面版使用。明确的“在 D 盘创建一个 tankGame 文件夹”会先填入该位置供核对，不向文字模型请求伪执行。桌面版调用系统目录选择器；网页原型通过本机适配器选目录或输入绝对路径并由服务端校验。普通附件上传只提供文件副本，不冒充已获得原文件夹的持续读写能力；浏览器不支持的选择方式应说明替代入口。
3. 将打开的文件夹登记为该项目的根目录，同时作为默认工作目录和默认产物位置，具体规则见[项目根目录与输出位置](#project-root-output)。展示项目名称、规范化后的根路径、所在设备、是否 Git、现有访问策略和可用能力。选择目录本身不运行脚本、不安装依赖、不递归上传内容，也不自动初始化 Git。现有有效授权覆盖时直接复用，仅缺少实际范围时才申请补充。
4. 用户发送第一条消息时创建会话；普通会话文字按[当前自动归档规则](knowledge-learning.md#local-chat-archive)保存到本机，用户可选择临时会话。归档不等于提取长期记忆或保存未发送草稿；当前草稿仅在页面内保留。保存失败明确显示，不能显示“已保存”。
5. 挂载根目录先显示文件树和可检索状态；用户选中文件、`@` 引用或任务需要时按范围读取。新增附属目录单独展示，不自动改变项目根目录或默认产物位置；目录引用、文本片段和外发范围都能在上下文面板查看。
6. 重新打开已保存项目恢复会话记录、面板位置与任务关联；实时任务从账本读取。不会因为重开会话再次执行历史消息，归档不会停止或删除关联任务。

| 特殊情况 | 用户可见结果 |
|---|---|
| 无项目聊天 | 可聊天和附单次文件；需要保存产物时明确选择目的地，不默认写入整个用户目录 |
| 非 Git 文件夹 | 项目与文件检索正常工作；工作树/分支按钮不可用并解释原因 |
| 根目录改名、磁盘拔出或远端离线 | 显示“路径不可用”或“设备离线”，保留草稿与历史，提供重新定位；不会自动改到另一个同名目录 |
| 重复挂载、大小写和连接路径 | 本机适配器规范化并展示真实目标；符号链接/目录联接越界不扩大授权；完整安全语义仍归安全章 |
| 切换项目或电脑时尚有草稿 | 草稿保留在原会话，新工作位置重新列出可用附件和范围；不能把旧项目引用隐式带入新项目 |
| 会话正在运行时换目录 | 提供“在该目录新建会话”；已受理任务保持原绑定，不能中途重新解释相对路径 |
| 多会话改同一文件 | 显示冲突与最新文件版本，复核差异后再写；Git 项目可选择独立工作树，不能把多会话当作天然隔离 |

桌面壳和当前网页只共用一套工作台与服务接口；是否引入 Tauri 等壳由[技术栈](stack-project-layout.md#workbench-host-choice)决定。

<a id="project-root-output"></a>
#### 项目根目录与默认输出位置

**按用户明确要求采纳（accepted）：打开哪个文件夹，就以该文件夹作为该项目的根目录；产生的文件内容没有明确指定其他位置时，默认保存在该根目录下。** 本条是已确定的产品规则；0.1.11 的项目登记和单份文本保存已实现，[验证范围](delivery-validation.md#project-workspace-evidence)不涵盖下表所有未来能力。当前输出指向由用户在输入区或保存框明确填写，尚不解析任意自然语言输出路径、项目规范或持久输出设置。0.1.74 仅对明确创建文件夹的有限表达准备项目路径，不把它扩大成通用文件写入工具。

| 情况 | 位置解析规则 |
|---|---|
| 未指定位置，或只给出文件名 | 直接使用项目根目录，例如打开 `H:\ExampleProject` 后生成 `报告.md`，保存为 `H:\ExampleProject\报告.md`；不擅自改到下载、桌面、临时目录或另建 `outputs` 目录 |
| 指定项目内相对路径 | 相对项目根目录解析，例如 `docs/报告.md` 对应 `H:\ExampleProject\docs\报告.md`；按已明确的路径创建必要子目录 |
| 明确指定绝对路径或其他目的地 | 按本次要求保存；用户已明确设置的项目输出目录或适用项目规范中的明确目录也属于指向，本次更具体的要求优先；路径仍须满足既有授权 |
| 仅打开/引用某个文件或挂载附属目录 | 不改变默认输出位置；修改现有文件仍写回所指定的原文件，不能因引用附件而将新产物默认写到附件旁 |
| 明确选择工作树或另一工作位置 | 作为本次任务显式指定的位置，受理前展示其真实根路径；不把它的输出写回原项目目录，不暗中修改项目根目录登记 |
| 根目录不可写、丢失或离线 | 展示实际失败原因并保留任务/草稿，不静默改存其他位置；需要替代位置时再由用户指定 |

项目内新会话继承该根目录及明确设置的输出指向；不同项目分别保存配置。任务受理时固定本次根路径、执行设备与已解析的输出位置，工具内部切换当前目录、切换界面或引用其他资料都不能改变这次落点。输入区可查看默认位置，产物卡显示最终完整路径并支持打开所在文件夹；已有有效指向时不必逐次询问保存位置。

文档、图片、代码、表格等面向用户的最终文件遵守上述规则。生成工具若先返回临时文件，交付步骤须将其落到本次目的地并核验，再报告已保存；只存在于缓存不能冒充已经保存在项目。系统自身的凭据、模型、任务账本、日志及临时缓存仍按[运行数据结构](stack-project-layout.md#project-structure-3)管理，这些内部记录不替代用户可见交付物。

#### 项目资源、文件编辑与工程文件（0.1.27）

**implemented，局部 verified。**“打开文件夹”后进入项目工作区（0.1.29 起采用下述独立右侧面板）：按需展开文件树，打开代码、脚本和文档；不需要先登记 README，也不要求项目使用 Git。原 Jarvis 标识、动效、配色和对话入口保留。文件树只列目录元数据，点击支持的文本文件才读取正文；查看文件不会自动发送给模型。

| 操作 | 当前行为 |
|---|---|
| 打开与切换 | 文件标签与项目绑定，切换项目、返回对话不会丢掉本页编辑草稿；顶栏“项目文件”图标始终保留；未选项目时点击选择文件夹，选定后可展开或收起编辑区 |
| 编辑与保存 | UTF-8 文本编辑、行号、Tab 缩进、Ctrl/Cmd+S；保留 UTF-8 BOM 与统一 CRLF/LF。混合换行会规范为 LF。成功回执后显示“已保存” |
| 新建文件夹 | 点击“＋ 文件夹”，填写项目内相对路径；上级目录须存在，重复请求返回已有目录，不创建到项目之外 |
| 新建文件 | 输入当前项目内路径，在编辑器编写，保存时独占创建；上级目录须已存在，不覆盖不同内容的已有文件 |
| 外部修改 | Cursor、其他程序或另一页签修改文件后，保存会报告版本冲突；保留页面草稿和磁盘内容，用户可明确重新读取核对。关闭脏标签、重新读取脏文件和离页均提示未保存修改 |
| 工程设置 | 保存根目录内的 `.jarvis-workspace` 文件，记录文件夹、已保存文件的标签位置、活动文件与额外排除项。工程不装入正文、未保存草稿、聊天、Key、MCP 命令或技能授权 |
| 重开工程 | 在“打开文件夹”输入工程文件完整路径，恢复该根目录及已保存视图；相对根路径使整个目录可搬迁。当前单根工程，不宣称兼容 VS Code `.code-workspace` |

文件树按文件夹逐层读取；默认排除依赖/构建缓存、Git 内部目录和常见凭据路径，可在工程设置补充排除项。无监听器、递归全文索引、语言服务器或额外常驻服务。具体类型、容量和预期版本写入规则由[资源契约](contracts.md#project-resources-contract)统一定义，保护范围归[文件编辑边界](security-sovereignty.md#project-editor-boundary)。文件名排除不是完整的敏感内容检测。

当前提供轻量文本编辑器，尚无语法高亮、代码补全、调试器、脚本运行、文件移动/删除、多根工程或差异合并。文件编辑不是 AI 自主修改权限；“AI 资料范围”仍是独立的可选检索设置，见[下节](#project-knowledge-ui)。后续按模块补充搜索、语法能力与任务驱动读取，不把编辑器、检索库和任务执行器合成一个不可替换的大组件。验证见[0.1.27 证据](delivery-validation.md#project-resources-evidence)。

#### 可调整的导航、聊天与右侧工作区（0.1.29）

**implemented，局部交互验证见[本次证据](delivery-validation.md#workbench-layout-evidence)。** 左侧只负责项目和会话导航；聊天拥有独立内容区；文件目录与文件编辑属于右侧工作区，通过标签切换。打开资源不再替换整个聊天页面，也不在左侧叠加第二个常驻栏目。沿用 Jarvis 的品牌、动效与主题。

```text
┌ 项目与会话 ┐ ┌ 顶栏：导航开关、当前会话、项目文件开关与既有工具 ┐
│            │ │ 聊天内容与输入框     │ 项目名称  放大 / 收起    │
│ 项目 A     │ │                      │ [项目文件] [main.py ●] │
│   会话一   │ │                      │ 目录或选中文件的内容    │
│ 独立会话   │ │                      │ 保存状态 / 光标位置    │
└────────────┘ └──────────────────────┴────────────────────────┘
        ↑ 可拖动边界                         ↑ 可拖动边界
```

| 使用场景 | 已实现的交互与状态规则 |
|---|---|
| 左侧导航 | 拖动右边界调整宽度（180–360 CSS px，按窗口约束）；顶栏可收起/展开。项目与会话始终是一套导航，文件树不占其位置 |
| 并排工作 | 右面板默认 520 px，可拖动左边界。文件区最小 320 px，聊天保留约 360 px；根据实际剩余空间限制拖动，不让另一侧被压到不可用 |
| 查看目录 / 编辑 | “项目文件”为固定标签；打开文件建立文件标签。目录和编辑在同一区域切换，文件名带 ● 表示草稿未保存。目录展开状态、同页文件选择和光标/滚动状态按项目或文件保存 |
| 专注与收起 | “放大”使用主工作区，“恢复并排”返回双区；× 或顶栏项目文件开关收起右区，保留缓冲。点击会话在专注/窄屏模式返回聊天；宽屏并排时继续保留文件面板 |
| 键盘与触控 | 分隔条可获得焦点，左右箭头每次 10 px、Shift+箭头 40 px，Home/End 到边界；双击恢复该边界默认宽度。支持 Pointer Events / pointer cancel。Ctrl/⌘+Alt+B 切换导航，Ctrl/⌘+Alt+E 切换资源；宿主截获快捷键时仍可点按钮 |
| 文件操作 | 文件区聚焦时 Ctrl/⌘+S 保存当前文件；在聊天输入时不会误保存文件。A−/A+ 调整编辑文字（11–22 px），不改变整个页面；Esc 在文件区收起面板，弹窗有优先权 |
| 窄窗口 | 窗口小于 900 px 时左导航变为可关闭抽屉；主区不足 720 px 时只显示聊天或文件。关闭文件立即回到原聊天，不把多个窄栏挤在一起。窗口变宽恢复先前布局偏好 |
| 布局记忆 | 浏览器只持久保存导航宽度、右区宽度、导航隐藏偏好和文字大小；“项目文件 → 更多 → 恢复默认布局”重置布局。布局配置损坏或存储不可用时使用默认值 |
| 会话失效 | 文件请求报告过期后显示“重新连接”。用户点击后从同源页面重新取得会话令牌，只刷新目录，不重放写文件、发送聊天或工具执行。编辑与聊天草稿仍在原页；保存须再次明确点击 |

**收起面板不等于关闭文件或卸载模块。** 关闭有修改的文件标签、重新读取及离页仍走原有提示；刷新/关闭浏览器会失去未保存文件、未发送聊天与附件，布局记忆不是草稿恢复。工程文件的内容范围仍由[项目资源契约](contracts.md#project-resources-contract)定义，不把 UI 偏好塞入工程或共同体记忆。

参考 [VS Code 自定义布局](references.md#s166) 的独立侧栏、视图切换与布局恢复，以及 [Codex 窗口布局命令](references.md#s167) 的并排、完整视图与隐藏面板。这里采用轻量实现，不宣称复制其完整 IDE 能力；自由停靠、多编辑器网格、语法补全与跨刷新草稿恢复仍未实现。模块分工见[架构边界](architecture.md#project-extension-modules)，重连边界见[安全约束](security-sovereignty.md#project-editor-boundary)。

#### 个人、工作和共用记忆的管理体验（局部实现）

#### 聊天中的个人指令（0.1.39）

在普通会话输入下列完整指令即可；无需打开项目，也不调用模型。支持中文/英文冒号，记忆名称与内容之间使用 `=` 或 `＝`；记忆类带冒号的指令可加“请”。不带冒号的一般描述仍作为普通聊天，不承诺自动识别。

| 输入示例 | 结果 |
|---|---|
| `记住：饮品=喜欢无糖茶` | 保存通用明确事实；`记住：我喜欢无糖茶` 也可，名称取前 60 字 |
| `修改记忆：饮品=喜欢黑咖啡` | 精确定位并替换正文，保留原范围与接入方授权；不能用新的“记住”静默覆盖不同旧值 |
| `忘记：饮品` | 清除该事实；原聊天与导出仍保留 |
| `查看记忆` / `查看记忆：饮品` | 本机显示通用事实，可用完整标识解决重名；最多显示前 20 条 |
| `记住本项目：术语=…` / `修改本项目记忆：术语=…` / `忘记本项目：术语` / `查看本项目记忆` | 仅作用于当前项目；没有选择项目时拒绝，不转为通用事实 |
| `设置交流风格：温暖` | 可选自然、简洁、温暖、严谨、幽默 |
| `设置相处方式：伙伴` | 可选助手、伙伴 |
| `设置称呼：小林` | 0.1.62 起保存称呼；也可在“记忆与接续 → 交流设置”一次修改三个表达字段 |
| `查询三库：UNKNOWN` / `查看能力` | 本机显示版本、来源和历史状态冲突，不触发执行 |
| `查看交流设置` / `撤销交流设置` / `恢复默认交流设置` | 查看当前修订、切回上一版或恢复自然/助手 |

新记忆默认仅本地；如需云端回答采用，在记忆面板逐项勾选接入方。交流设置包含称呼和上述表达枚举，保存后用于后续普通对话，包括所选云端模型；细则归[基础人格运行范围](#persona-runtime)。临时会话拒绝个人状态指令的查询和修改；公共三库查询仍可使用，也不采用持久表达设置。关闭记忆使用时，记忆指令提示先开启；交流风格设置独立于事实记忆开关。

附件、显式技能与个人指令不能混用；文件生成模式须先关闭。处理本地指令时发送按钮显示“正在处理个人指令”，不把它当作可随时丢弃的模型输出；全局核心停止仍按原机制约束新写入。只有本地事务成功才显示“已记住/已纠正/已忘记”。网络断开或超时先用查看指令或面板核对，不自动重发。使用帮助折叠在现有顶栏记忆面板，不新增常驻输入工具条。0.1.62 的交流设置页提供保存、撤销上一版、恢复默认和刷新；加载期间禁止编辑以避免旧响应覆盖输入，修订冲突保留输入并要求核对。正在回复不阻止打开这些面板，修改只作用于下一轮。

| `忘记接续：旅行计划` | 清除接续正文，排除其派生历史；原聊天与导出仍保留 |

支持中文/英文冒号、`=`/`＝`、`｜`/`|`，带冒号的指令可加“请”；标题也可替换成记录的完整标识。普通叙述、引用示例或模型回答不自动变成接续。保存/更新前，页面等待原消息确实归档；失败时显示原因并保留输入，不显示保存成功。

0.1.62 起可输入话题并点击“按话题推荐”，最多显示三条词法相关记录，核对来源后再勾选；自动路由未确定接入方时以本地范围预览，后续云端请求仍重新检查许可，不因此放宽外发。

在“接续”页可查看进展、下一步、状态、修订、来源会话，勾选“用于本会话”，保存云端许可，标记完成、重新打开和忘记。新会话默认不选记录，最多选择三条；选择随会话归档保存，刷新后恢复。“继续话题”将当前选择替换为指定的一条。来源链接另开原会话，保留当前对话与草稿；链接标明原消息位置，不承诺自动滚动定位。

新记录默认只供本地模型使用；云端续聊先在卡片勾选相应接入方并保存许可。选中的记录全部不可用时明确停止本次模型请求，要求核对许可/来源或取消选用；部分不可用则提示并仅使用有效记录，预算不足不截断一条记录。记忆开关同时控制接续装配。临时会话不使用或修改接续，面板仍可显式查看本机列表；关闭该面板即可继续临时聊天。

数据来源、范围和失效规则归[接续数据语义](knowledge-learning.md#continuity-runtime)。这一步没有自动摘要全部旧聊天、安排提醒、主动启动任务或自动进化。

#### 从普通表达整理记忆与未结事项（0.1.43 起，0.1.50 补语义候选）

普通会话中，本人文字消息下新增轻量“整理为记忆…”入口；点击后展开可关闭的对话框，先显示原句，再显示候选事实/未结事项。标题与关闭按钮在滚动时保留，窄屏使用单列；不新增常驻侧栏或顶栏文字按钮。当前需开启会话记忆，并先完成本机会话保存；临时会话会说明不能创建持久候选。

例如发送“我更喜欢简洁回答。我们下次继续讨论学习计划。”后，点击整理，可分别修改偏好及学习计划的名称、内容和下一步，选择范围，然后“确认并保存”；也可逐项“忽略”。未匹配时说明当前中文规则范围并给出明确记忆/接续命令。保存状态逐项显示；关闭未保存候选不写入任何长期记录，也不会启动提醒或执行工作。

响应丢失可重试同一内容，界面说明回执已处理时到原记忆面板核对，不把重传冒充新的保存。保存后的事实继续用原面板/明确命令纠正、遗忘和设置接入方许可；未结事项在“接续”中选择，或新会话输入“继续话题：名称”。确认本身不改变本轮原消息、草稿或已发出的模型请求。来源与遗忘边界见[数据语义](knowledge-learning.md#personal-candidates-runtime)。

**0.1.44：**事实卡片可展开“查看来源”，核对原句及会话位置。原句被修改、删除或暂时无法核对时，卡片显示“暂停用于回答”，保留内容供主人处理；可编辑纠正、遗忘，或点击“确认独立保留”将这条事实改为主人的独立确认。后者不扩大原来的模型接入方许可。来自同一原句的同一候选，纠正或遗忘后不能通过换名称、改内容或换范围再次保存；仍可明确提出新的记忆要求。旧版无来源记录的事实不虚构来源。完整状态和边界只维护在[候选事实来源规则](knowledge-learning.md#candidate-fact-provenance)，实测见[本轮验收](delivery-validation.md#memory-provenance-evidence)。

**0.1.50：**同一窗口先显示不耗模型调用的规则结果；可选择具体模型和档位，查看整条原文的发送去向，再点击“用此模型重新整理事实”。返回后模型设置折叠，让原句、可编辑候选、类型/主体和日常/工作用途优先显示；可展开修改模型，或逐项忽略。客户信息、虚构角色不默认当成主人资料。每次重新整理替换未保存的预览，不自动保存或合并；仅提取事实，未结事项仍用原规则。

整理过程中可停止或关闭窗口；停止后不接收迟到候选。保存时只冻结当前候选窗口，不阻塞后台任务；已保存字段锁定，去原记忆面板修改。响应丢失后相同确认可以重试；过期或宿主重启则重新整理。界面显示模型返回的用量，缺失时明确说明未返回；关闭临时预览不删除源会话。完整语义与范围归[按需语义候选](knowledge-learning.md#semantic-candidates-runtime)，实测归[验证记录](delivery-validation.md#semantic-candidates-evidence)。

2026-10-18 增量：若整理后记忆已经被修改或忘记，确认入口会显示旧预览未保存，禁用本批旧候选的保存按钮并保留编辑文字；主人可核对后点击“用此模型重新整理事实”。界面不会自动再次调用模型，也不把修订冲突提示为继续重试旧预览。具体失效规则归[候选接口](contracts.md#semantic-candidates-contract)，实测见[多轮验证](delivery-validation.md#memory-lifecycle-evidence)。

<a id="composer-design"></a>
### 输入区：每个入口做什么

输入区从上到下是**工作上下文条 → 附件与引用 → 多行正文 → 操作工具栏 → 本次状态**。上下文条始终显示项目/目录、执行电脑和临时/保存状态；选中云模型时，靠近发送处显示实际资料处理去向。“执行电脑”和“模型在哪里推理”是两个独立字段。

| 控件 | 功能与展开项 | 边界及反馈 |
|---|---|---|

| 实时语音 | 后续进入听说界面，显示输入/输出设备、转写、静音、结束 | 不因打开设置启动录音；打断和身份语义见[语音链路](#interaction-tasks-2) |

| 停止生成、取消任务 | 发送按钮切换为停止当前回复；任务中心取消选定任务 | 作用域始终明确；取消显示处理中直到回执；助手继续运行或待命，详见[生命周期](#personal-assistant-lifecycle) |
| 用量与状态 | 本次耗时、处理去向、实际模型、可获取的 tokens/费用；缺失显示“未返回” | 不编造账户余额、上下文剩余量或计费数据；失败与 UNKNOWN 明确区分 |

输入状态统一为：**空白可编辑 → 附件准备/校验 → 可发送 → 提交中 → 已受理/运行中 → 完成、失败或结果未知**。同一提交重复点击不能重复接纳；提交失败恢复原文本和引用。断线后按请求标识查询已有结果，不能自动把请求当成失败重发。上下文超限先展示将缩减的内容和摘要来源；仍超限保留草稿并指出需缩短的部分。

“追加指导”交给当前任务在可接受的边界处理，显示已接收/尚未应用；“下一轮发送”进入会话消息队列，可撤回为草稿。这是会话队列的设计，不能与现有浏览器 FIFO 混用状态。完整任务执行与恢复仍由[任务章](tasks-agents.md#interaction-tasks-3)拥有。

0.1.37 的[本地精确计算](core-bootstrap.md#calculator-entry)直接复用输入框和发送按钮，结果详情标注实际本地来源；上下文报告说明未调用模型、只处理当前完整算式。模型目录不可用时，显式 `/计算` 仍可发送，其他普通模型请求保持不可用。没有新增顶栏入口；语法与冲突语义只在[计算分流规则](models-offline.md#deterministic-calculation-runtime)维护。

#### 文件、图片与拖拽输入（0.1.21）

**已实现。** 对话页可拖入文件，输入框“添加附件”可多选，`Ctrl+V` 可粘贴截图；文字和链接拖入输入框成为可编辑草稿。附件卡片显示文件名、大小、读取状态和图片缩略图，支持移除、读取失败后重试。只有附件也可发送，应用补入“请分析这些附件。”作为问题。

- 支持 PNG、JPEG、WebP，以及文本、代码、Markdown、CSV、JSON、YAML 等可读文件。文字按 UTF-8 或带 BOM 的 UTF-16 解码；不静默截断或强行解码二进制。PDF、Office 文档、压缩包、音视频尚未解析，卡片说明转为文本或截图的替代方式。网页链接只成为文字，不自动下载远端内容。
- 交互上限：每条 8 个附件；单张图片 4 MiB，图片合计 8 MiB；图片边长不超过 8000 像素、总像素不超过 2000 万；单个文本文件 48 KiB，正文与文本附件共同计入现有输入限制。模型上下文仍可能更小。接口定义见[附件契约](contracts.md#chat-attachments-contract)。
- 选择和拖入只读所选副本，在当前页面内存准备；发送时才交给所选接入方。草稿附件随原会话保存，切换或新建会话不会混用。停止或失败时恢复原问题与附件；若已有新草稿，保留新草稿并提供恢复原附件入口。刷新或关闭页面会清空草稿附件；0.1.24 起普通会话文字按[归档规则](knowledge-learning.md#local-chat-archive)保留，附件内容仍不存入归档、浏览器存储、项目目录或诊断账本。
- 已发送附件显示在对应用户消息下；后续上下文携带附件内容，达到限制按整轮裁剪并提示。图片只走已接通图片协议的模型；本地纯文本模型及未确认能力的自定义模型会提示改选。供应商或账户仍可能拒绝某个模型，不把模型目录标注当成实测成功。
- 附件不是项目授权或文件夹绑定，不改变[项目根目录与默认输出位置](#project-root-output)。导入代码不会执行，图片不会自动启动工具；生成文件仍走现有保存流程。

界面与协议子集的验收范围见[0.1.21 证据](delivery-validation.md#attachments-evidence)，本节不宣布完整 V-UI 输入工作台已经通过。

#### 在聊天中提出改进并取回结果（0.1.68）

**新增编码改进入口：**在普通项目会话输入 `/改进 修复求和工具`，或在 `/成长进度` 面板点击“新建编码改进单”，会打开已有技能输入区并勾选“先建立改进单，验收后回填结果”。填写源码路径、公开示例、独立验收、编码提供者及构建格式后发送，先看到待开始的改进单，输入区回到普通对话以便继续聊天。查看文件基线、模型、调用/时间上限后点击“开始编码与独立验收”。缺少必要案例时保留草稿，不猜测业务期望或静默调用模型。

编码卡片与原目录报告卡片共用成长面板，区分“需求已冻结 → 编码任务 → 独立验收 → 结果回填”。完成后“查看差异、验收与应用”打开已有右侧可缩放工作区，继续使用应用、恢复与下载入口；失败也能查看诊断。只有经过独立验收的候选显示核验完成；不会将报告交付成功显示为能力已发布。取消、重新分析及刷新接续保持可见。规则归[编码工作流](tasks-agents.md#bounded-coding-workflow)，证据见[本轮验收](delivery-validation.md#coding-demand-evidence)。

日常聊天通过以下明确入口使用[需求成长通路](evolution-release.md#demand-growth-runtime)，不常驻占用侧栏或输入框。

| 操作 | 看到什么 |
|---|---|
| 先用 `/任务 列出样例目录文件并保存报告` 完成报告 | 原本会话任务回执及核验结果 |
| `/改进 把最近的目录报告导出为 TSV`（也支持 CSV、Markdown） | “需求与成长”面板：来源、记录数、分析时的能力基线、模型、最多候选数及验收摘要；分析本身不计模型用量 |
| “使用现有能力导出”或“补齐能力并导出” | 同一单进入执行，显示需求、候选、验收、能力可用与本次交付阶段；没有完成的阶段不标成功 |
| 关闭面板继续聊天 | 已启动的后台工作继续，普通回复不等待代码生成；停止聊天不等于取消成长 |
| `/成长进度` 或回执中的“查看改进与结果” | 当前会话状态、取消入口、实际输出与下载；刷新后保留回执链接 |

面板可关闭，窄屏内容换行；活动单有轻量边框动效，遵守减少动态偏好。仅在面板打开且页面可见时每 4 秒查询本机状态，不触发模型或额外自检。已有设置中的模型选择、包记录和回退入口继续复用；不改变顶栏图标规则或新增常驻工具栏。

分析回执丢失时保留原请求编号并提供核对，不新建第二单；错误与 UNKNOWN 按实际记录展示。临时会话、未保存会话、附带附件或开启文件输出时说明原因并保留输入；报告格式改进仍需已有成功报告，编码改进则需要项目及冻结案例。所有控制消息独立于普通模型历史。原报告通路实现与真实模型测试见[验证记录](delivery-validation.md#growth-demand-evidence)。

**0.1.43 中断后的恢复入口：**在接续关联里点击“打开来源会话”，通过回执或 `/成长进度` 核对原单。失败、中断、未知和已取消记录直接显示“重新分析这项需求”，不再要求手写原需求。点击只形成待开始的新单，保留旧回执，并展示重新核对的来源、模型、能力基线及原单引用；来源采用本会话最新已核验报告，因此仍需核对新单。已有能力时随后选择“使用现有能力导出”；需要补齐时明确开始编码，后台工作仍可与聊天并行。

UNKNOWN 会额外提示先核对远端用量和已有产物；重新分析不把原结果变成失败或成功，也不取消原费用。新的单独开始操作遵守原预算和验收。输入框草稿保留；响应丢失用原请求编号查询，未确认时不自动重发。原接续关联不自动改指新单，可在面板明确调整。实测见[恢复与候选验证](delivery-validation.md#recovery-candidates-evidence)，普通任务的 UNKNOWN 仍按原任务规则核对，不承诺任意任务一键恢复。

在编码表单的“构建格式”选择“JSON 查询工具包 · 自带离线依赖”，可用 JMESPath 处理嵌套 JSON。待开始卡显示配方，验收后右侧结果可下载 PYZ；“离线使用与重建”说明依赖随包提供及源码应用方式。旧无依赖配方仍为默认。完整约束见[离线依赖配方](toolchains.md#bounded-python-dependencies)。

0.1.70 在原表单增加“Python 包”和“JavaScript · 新建交互场景”，显示相应文件数/入口说明。包或场景可填“明确新增的文件路径”；它们也必须出现在源码清单。场景成功后右侧结果新增可展开预览，支持播放、相位及部件展开，下载 ZIP 后可离线打开 scene.html。切换配方保留草稿，隐藏字段不提交；所有详细范围只链接[配方规则](toolchains.md#bounded-package-scene-recipes)。

### 侧栏、搜索、会话与工作面板

**项目会话树（2026-10-16，0.1.27 增量 implemented）：**聊天左栏用“文件夹项目 → 缩进会话”展示，不再分成项目路径卡片与独立的当前会话大按钮。点击项目行展开/收起，悬停显示根目录；行末加号在该项目内新建对话，新对话直接进入聊天。点击会话恢复正文及当前页面保留的草稿，当前项使用圆角高亮。无项目会话集中在“独立会话”；长标题省略并提供完整提示。折叠偏好保存在当前浏览器，恢复或新建会话时展开所属组。当前会话回复中显示转圈，临时会话显示虚线标记，保存失败显示感叹号并提供文字提示；这些状态不代表其他会话正在后台执行。当前原型在回复期间仍禁止切换会话，发送位的停止按钮只取消当前回复。

侧栏按固定项、最近会话和项目组织，支持重命名、移动分组、固定、归档和恢复。归档是可恢复的列表整理；“删除会话”“移除项目关联”“删除磁盘文件”是不同操作，文案必须写清对象。全局搜索提供会话、项目、文件、任务、记忆的类型筛选；结果带项目、路径、命中片段与时间。文件搜索默认限当前已授权项目，搜不到时区分“无命中”“尚未索引”“无权限”和“设备离线”。

|---|---|---|
| 会话 | 用户消息、可折叠执行摘要、来源、模型/节点、产物、验证结论 | 复制、选区引用、编辑后新分支、从此处新会话、导出；旧消息不被静默改写 |
| 文件 | 文件树、路径/类型搜索、文本编辑、Markdown/图片预览 | 打开、搜索内容、引用选区、查看差异、保存；大文件分段，二进制不强行文本解码 |
| 差异与审阅 | 修改列表、前后对照、检查结果、对应任务/版本 | 查看问题、接受选定修改、拒绝候选；“接受”须按当前文件版本复核，不能覆盖用户后续编辑 |
| 浏览器 | 地址、来源、标签、截图/批注及相关任务入口 | 打开/刷新/返回；执行任务另显示目标、范围与状态；具体边界见[浏览器安全](security-sovereignty.md#computer-boundary) |
| 任务中心 | 运行、排队、等待用户、暂停、完成、失败与未知；项目/设备筛选 | 查看进度、预算和证据，暂停可暂停任务、继续或取消；不支持检查点的任务不能显示假暂停 |
| 产物 | 文件名、保存位置、格式、生成任务、版本和验证状态 | 预览、在文件夹中打开、引用到后续会话；生成成功与验收通过分别显示 |
| 日志/终端 | 按需显示任务输出、退出码、错误及命令工作位置 | 复制错误、定位任务；终端是实际命令入口，受能力与授权约束，不默认开放任意执行 |

普通聊天无需展开每个底层调用；活动条能展开“做了什么、在哪里做、结果与证据是什么”。不展示模型隐藏思维链作为验证证据，不用动画进度代替真实任务状态。未读数、错误数与等待操作数分开；只有新结果、失败或需处理事项触发相应通知，偏好可调整。

### 项目详情、编辑与列表整理（2026-10-17）

**implemented，验证范围见[项目菜单证据](delivery-validation.md#project-management-evidence)。** 每个项目根行右侧增加独立的“…”按钮，位于新建聊天按钮之前；“…”始终可见，带独立按钮边界，不再依赖悬停发现。点“…”、右键项目行或点击输入区上方的当前项目名称，打开同一个项目详情菜单；文件夹行仍负责展开/收起聊天。菜单显示项目名称、同页聊天数量和根目录，名称过长省略并保留完整提示。

| 操作 | 当前行为 |
|---|---|
| 编辑项目 | 修改 Jarvis 中的显示名称、项目说明和所属分区，根目录只读。说明用于本机管理展示，不自动成为模型提示、记忆或执行授权；名称不重命名磁盘目录 |

| 分区 | 通过子菜单移动到已有分区、未分区，或打开编辑框填写新分区。一个项目属于一个分区，置顶只改变显示位置，不丢失分区 |
| 在资源管理器中打开 | 打开当前项目已经登记的根目录；菜单路径本身也可点击打开，另有复制项目路径。目录丢失、替换或不可达时报告失败 |
| 归档聊天 | 先等待当前普通会话保存完成，再归档本项目当时已经保存且未归档的聊天；从正常列表隐藏，不删除正文、文件或资料。临时会话、未发送草稿和其他项目聊天不被批量归档。归档后当前项目进入新的空会话，同页旧草稿仍随原会话保留 |
| 已归档聊天 / 恢复 | 项目菜单及项目聊天列表提供恢复入口；逐条恢复后返回正常列表，可继续选择聊天。自动保存旧会话不会撤销归档标记 |
| 移除项目 | 明确提示仅从列表移除，可取消。根目录、聊天、文件、输出记录与记忆/资料登记全部保留；移除当前项目后进入独立会话，当前页面的旧草稿和文件编辑缓冲仍保留 |
| 恢复项目 | 左侧“已移除项目”提供恢复入口；明确再次打开原文件夹/工程也可恢复，继续使用原稳定项目 ID。移除不释放底层项目登记的 200 项容量 |

菜单可点击空白处、Esc 或 Tab 收起，用上下箭头和 Home/End 移动焦点；弹窗与菜单提供明确名称。位置按窗口边界约束，长菜单允许滚动。项目资料/事实的既有检索范围不因“移除列表项”被撤销；需要停止检索应使用[AI 资料范围](#project-knowledge-ui)或[记忆面板](#explicit-memory-ui)。所有状态只在收到后端成功回执后更新；多页面编辑冲突保留输入，取消后刷新页面核对再编辑，结果不明时不自动重放系统资源管理器操作。

项目组织由独立模块维护，复用既有目录和聊天身份；不接管文件编辑、任务调度或模型路由，见[模块职责](architecture.md#project-extension-modules)。精确字段、上限与重试语义归[组织契约](contracts.md#project-organization-contract)，保护边界归[项目目录](security-sovereignty.md#project-workspace-boundary)。当前无拖动排序、批量删除文件、移动磁盘根目录或跨设备组织同步。

### Jarvis 专属体验与功能入口

下表是 Jarvis 的差异化设计契约，不是“其他产品永远没有”的断言。每个入口显示**可用 / 未安装 / 未配置 / 规划中 / 不可达**；设置页可以展示规划说明，主操作区不提供看似可执行的假开关。

| Jarvis 入口 | 用户能看见和设置什么 | 专用语义的唯一权威 |
|---|---|---|
| 离线生存 | 本机可用模型/工具、网络状态、离线可完成事项、缺失依赖和降级原因 | [离线生存](models-offline.md#local-survival)；“断网仍可用”必须来自实际安装与验收 |
| 记忆证据台 | 本次引用的事实、原始来源、有效时间、冲突、纠正/遗忘、项目与私人域、外发设置 | [记忆设计](knowledge-learning.md#memory-selection-design)；会话记录不自动成为长期事实 |
| 多设备共同体 | 节点身份、在线状态、能力、任务所有者、同步水位与冲突；选择工作电脑 | [共同体](federation.md#offline-federation)、[记忆同步](federation.md#memory-replication)；同步会话不等于同步全部项目文件 |
| 助手与任务状态 | 当前回复、后台任务、运行中/待命中；模型失效仍可查询状态 | [个人助手生命周期](#personal-assistant-lifecycle)；高级身份与全局监督属于延期设计 |
| 进化工作室 | 改进建议、候选版本、构建、对照评估、灰度与回退证据；允许的改进范围 | [进化与发布](evolution-release.md#self-evolution)；候选成功与正式启用分开显示 |
| 人格与形态 | 表达风格、称谓、声音、关系模式、化身、版本预览与回退 | [人格配置](#persona-embodiment)；不把人格主动性当作权限开关 |
| 资源与团队 | 前台响应保留、后台队列、模型内存、团队成员职责、并发/预算及退让原因 | [资源调度](tasks-agents.md#resource-scheduling)、[Agent 工厂](tasks-agents.md#agent-factory) |
| 虚拟世界 | 世界/角色、模拟时钟、分支、世界内记忆；明显的“模拟”标识 | [NPC 世界](simulation.md#npc-world)；真实设备与模拟动作入口分开 |

### 设置中心与配置生效规则

**当前入口（2026-10-16 设置归并增量，implemented）：**工作台顶部右侧提供“记忆”和“设置”图标，设置固定为最右一项；两者不再放在聊天左栏。图标无常驻文字，鼠标悬停或键盘聚焦时显示提示，并保留屏幕阅读器名称。模型供应商列表移到“设置 → 接入方与 Key”，在卡片内查看模型数量与接入状态；聊天输入区仍保留本次模型选择。设置在独立标签页 `/settings` 打开，原会话与未发送草稿继续保留。总览提供外观、接入方与 Key、模型与价格、用量总览、调用明细、后台任务等独立页面；旧 `/admin` 地址与分页面锚点继续可用。后台任务的表单、队列与记录共用原有服务，关闭设置页不取消任务、不退出助手。验证范围见[设置入口证据](delivery-validation.md#settings-navigation-evidence)。

**顶栏图标规则（2026-10-17 更新，accepted；当前入口 implemented）：**工作台上方偏右是统一工具区，从左到右为项目文件、会话保存与管理、离开工作台、助手状态、检查连接、音效、AI 资料范围、记忆、设置；项目文件入口始终可见，未选项目时点击打开文件夹选择；AI 资料范围按当前项目显示，设置始终最右。所有当前及以后新增的入口均须遵循：

- 默认仅显示功能图标，不常驻显示名称、项目数量或状态文字；复用 `icon-button topbar-action` 与同一尺寸、间距和焦点样式。
- 每项提供明确的 `aria-label` 和唯一的 `aria-describedby`，关联 `role="tooltip"` 的 `.topbar-tooltip`；鼠标悬停和键盘聚焦均显示文字。不能只依赖浏览器原生 `title`，也不能只用颜色表达状态。
- 动态状态同时更新提示文字和无障碍名称，不替换或移除图标；可切换控件提供真实 `aria-pressed`，弹窗/面板入口标明对应关系。纯状态指示不伪装为操作按钮。
- 窄屏可以将工具区排列到标题下一行，提示与展开菜单保持在视口内；触摸使用点击进入对应面板，面板仍有明确标题，功能不依赖悬停才能操作。
- 新增入口优先放在同类工具旁、设置之前；沿用统一组件，不另建文字按钮或重复占据左侧导航。完整管理表单仍归设置中的专用页面。

AI 资料范围的状态与行为见[项目资料](#project-knowledge-ui)。保存、运行和音效说明随真实状态更新；助手状态仅作指示，离开工作台不停止后台助手。

**0.1.63 网络入口（implemented）：**设置 → 网络与离线（`/settings#network`）提供“仅此软件离线”开关、保存结果和刷新核对。保存后跨重启保留，关闭时不会自动重发工作；不影响其他软件联网。完整行为和实际限制只维护于[应用离线控制](models-offline.md#application-offline-control)，验证见[应用离线证据](delivery-validation.md#application-offline-evidence)。

**0.1.66 编码协作入口：**设置新增[编码协作](http://127.0.0.1:18181/settings#coding)专页及总览卡片，可启用已有本机 Codex、选择模型与推理档位，并查看可用状态。在技能任务的编程副本入口填写文件、公开/留出案例与执行器；选择源码 ZIP 或可运行 PYZ 配方；结果在已有右侧面板查看差异、独立案例与真实工具包检查、下载工具/配套源码和应用/恢复文件组。面板可放大/恢复并排；“离线使用与重建”说明 Python 要求、输入输出与隔离边界。完整步骤归[编程工作流](tasks-agents.md#bounded-coding-workflow)，实测归[K3 证据](delivery-validation.md#k3-coding-evidence)。没有新增占据聊天左栏的管理入口。

**后续扩展规则（accepted）：**新增后台管理能力统一加入设置内的专用页面，并提供总览入口和可直接访问的页面地址；不再把供应商、Key、计费或诊断明细铺进聊天侧栏。聊天左栏优先留给项目与会话，不擅自新增全局工具或管理入口来占用宽度与纵向空间；此类入口优先复用顶栏或设置中心。入口可见不等于该能力已经实现，下方完整设置方案仍为 proposed。

设置页采用“左侧类别＋右侧表单”，顶部搜索可以按功能名定位设置。每项注明当前值来自全局、项目还是本次会话，并能恢复到上级配置；普通偏好按“会话覆盖项目、项目覆盖全局”解析，权限按实际授权取允许范围，不接受偏好覆盖。尚未实现的表单显示设计说明，不能假保存。

| 类别 | 设置项 | 生效时机/限制 |
|---|---|---|
| 通用与会话 | 语言、发送键、默认临时/保存、启动页、关闭窗口行为、跟进消息方式 | 普通偏好保存即生效；关闭窗口明确区分隐藏界面与停止服务 |
| 外观与快捷键 | 浅/深/系统主题、字体、字号、密度、侧栏宽度、减少动画、按键重映射 | 实时预览，可重置；快捷键冲突可见 |
| 项目与文件 | 项目根目录、附属目录、产物位置（默认根目录，可明确指定）、搜索排除、文件大小/类型限制 | 遵守[输出位置规则](#project-root-output)；新请求采用新配置，已受理任务不改目录绑定 |
| 模型与用量 | 默认模型、能力与推理偏好、允许的回退、预算、本地服务状态 | 下一轮生效；凭据通过独立凭据入口，不显示在导出或聊天上下文中 |
| 输入与语音 | 附件偏好、转写语言、输入/输出设备、按键说话、播报与打断 | 录音由明确动作开启；设备断开提示并回到文字 |
| 权限与隐私 | 文件、网络、工具、设备、数据外发、有效期、查看与撤销授权 | 显示实际有效范围；规则仍归[安全章](security-sovereignty.md#identity-authorization) |
| 记忆与数据 | 可用域、记忆使用、来源保留、纠正/遗忘、会话导出、备份与迁移 | 展示处理进度及失败范围；保留/删除规则归[知识章](knowledge-learning.md#memory-data-5) |
| 任务与自动化 | 并发、队列、资源预算、通知条件；未来已创建计划的查看/暂停/删除 | 默认不创建计划；只有用户已授权的计划才登记并启用 |
| 插件与技能 | 已装/可用版本、能力声明、依赖、启用范围、卸载影响 | 安装、授权与启用分别可见；未安装不出现在可执行命令列表 |
| 设备与共同体 | 配对节点、共享范围、同步策略、冲突和断联行为 | 默认不分享本机资料；完整协议归共同体章 |
| 人格、世界与进化 | 对应配置、版本、预览、允许范围与回退入口 | 保持真实/模拟边界；变更按各领域规则生效 |
| 健康与关于 | 版本、服务/依赖诊断、日志导出、运行/待命状态、说明文档 | 模型不可用时仍有确定性入口；当前不要求恢复密钥或密码 |

建议 Jarvis 初始快捷键：`Ctrl+N` 新会话、`Ctrl+O` 打开文件夹、`Ctrl+P` 搜索文件、`Ctrl+K` 命令菜单、`Ctrl+F` 当前内容查找、`Ctrl+,` 设置。普通网页可能被浏览器截获的组合必须提供等效按钮；快捷键只在适用焦点内生效。`Esc` 默认关闭菜单/抽屉，不把退出菜单误当成全局停止。

#### MCP 连接与技能管理（0.1.37）

设置左侧与总览统一使用“技能与工具”，内部提供“技能 / MCP 工具”标签；保留 `/settings#mcp`、`/settings#skill` 深链接。**0.1.55 增量接通 Context7 只读文档任务，其余连接保持各自实际接入状态。**技能当前可用范围独立见[技能管理](#skill-policy-management-ui)。管理操作不用模型；保存配置和规则不被显示为工具可调用。

MCP 页复用技能页的两列插件卡片、圆角、本地彩色 SVG、名称、用途、悬停说明与键盘详情；窄屏单列。首批十项分为编程与协作、搜索与研究、浏览器与测试、文件与资料、三维与创作，另接纳已有自定义连接。支持搜索和配置/停用状态筛选；一个完整 MCP 服务器是一张卡，内部工具不拆成菜单条目，同来源多个连接配置归到同一张卡。详情提供使用/不使用条件、依赖、维护方或社区类型、费用说明、来源审阅版本、可配合的技能及当前验证状态；“和技能怎样配合”给出流程示例，同类搜索服务说明按任务选择。

连接编辑使用维护方配置模板，支持本地 stdio 程序/参数或 Streamable HTTP 端点；编辑、刷新、格式检查和移除复用既有登记接口。旧自定义配置完整保留，不按名称猜测来源或自动关联。检查只验证配置格式，不将程序存在、依赖已安装、服务器可达、协议握手或工具可用混为一谈。凭据字段仅接收引用名称，尚未绑定真实凭据；模板不自动下载或启动服务。

全局、项目、会话可以保存“条件满足时选用 / 仅明确指定时选用 / 停用”，默认继承全局 auto。控件标为“选用规则”。卡片分别显示“推荐·待配置”“已配置·待接入”“可使用·按次连接”“已停用”，可调用计数来自适配器与规则检查。详情显示最近任务的时间和状态，明确历史成功不代表当前连通或额度。会话作用域以名称选择并带入所属项目，避免手工填写编号。恢复继承保留修订，过期写返回冲突并保留输入。完整选择规则归[MCP 选用](tasks-agents.md#mcp-selection-policy)，来源取舍归[MCP 选型](stack-project-layout.md#mcp-integration-choice)，管理实测归[MCP 证据](delivery-validation.md#mcp-management-evidence)。

技能页选择一个含 `SKILL.md` 的本地目录，保存来源与内容摘要；检查显示当前文本，变更后提示重新登记版本。文字按纯文本预览，附带脚本和外部指令不会在管理时执行。当前只检查文件存在、编码、大小及摘要，不声称已通过完整 Agent Skills 格式或技能质量评估。移除只删除登记，保留原技能目录。

聊天输入区提供“文档工具 · Context7”，填写库名称或明确库 ID，问题沿用当前输入框。结果通过“本会话任务 → 查看文档结果”展示库候选、来源文本和版本信息，支持下载调用回执；候选按钮只填写草稿，不自动外发。外部内容按纯文本显示，关闭或切换会话清理结果窗口。说明只发送库名与当前问题、零模型调用；不携带附件、历史或项目文件。文档模式及完整 `/文档 库名 问题` 命令不依赖配置模型，仍受核心就绪、输入状态与任务准入检查；没有模型时普通聊天保持不可发送。

普通聊天的文档意图候选通过“准备文档草稿”接续：点击时向宿主核对本条原文、库名、查询与当前作用域规则，通过后切换到文档模式，展示可编辑的库名和问题；实际外发仍由发送触发。已有草稿、附件、文件输出或正在回复时保持输入不变；检查期间新输入、切换会话或项目时也不覆盖。停用、未配置、来源不匹配等原因就地提示，不能把候选卡显示为任务已受理。候选原文检查、工具调用与模型识别的计费分别说明；只有文档查询本身为零模型调用。普通聊天候选接入状态见[统一对话的改造顺序](core-bootstrap.md#dialogue-upgrade-order)，条件与范围见[MCP 选用](tasks-agents.md#mcp-selection-policy)。

其他工具后续实际启用采用“登记 → 依赖/内容检查 → 能力发现 → 范围绑定 → 按需运行 → 停用/升级”的独立流程；执行状态、版本变化及失败原因必须真实可见，默认不为每个扩展常驻一个进程。模块与后续流程的权威定义见[扩展模块职责](architecture.md#project-extension-modules)，字段见[登记契约](contracts.md#extension-catalog-contract)。

**轻量动效与可访问性。** 无第三方前端依赖、WebGL、视频或模型调用；连续动画由 CSS 完成，只改变 transform/opacity，滤镜和遮罩不逐帧变化。指针事件用 `requestAnimationFrame` 合并，同一标识最多排队一帧；标识本体没有常驻 JavaScript 动画循环或计时器，组件移除时取消帧、释放事件监听与观察。所有光效图层复用同一 PNG URL，不引入额外位图或视频资源。遵循 `prefers-reduced-motion`，减弱动效时关闭悬浮、倾斜、扫光和光晕，只保留静态主图与焦点框；暂停按钮也禁止交互运动。没有持久保存动效偏好。普通 PC 的实际帧率和 GPU 占用尚未定量基准测试。品牌模块独立于模型、任务和记忆模块。

**验证范围。** [本轮品牌证据](../evals/reports/brand-ui.json)限定于 0.1.21 源码上的品牌增量；HTTP 资源白名单、CSP nonce、目录穿越拒绝及运行包资源完整性由 `tests/test_web.py` 覆盖。桌面与窄屏展示、鼠标移入/移开、键盘聚焦、暂停、休眠及新会话组件重建的实测结果以该证据为准；资产尺寸与摘要见 manifest。跨浏览器、系统高对比、系统减弱动效的实机切换及通知区新图标替换仍未验证；不据此宣布 [V-UI-14](delivery-validation.md#v-ui-14) 全部通过。0.1.23 上的[侧栏增量证据](../evals/reports/brand-sidebar-ui.json)覆盖工作台与设置页的真实 Edge 渲染、待机动画、悬停/移开、链接焦点、暂停、模拟减弱动效和 390px 布局；21 项网页测试通过，不新增模型调用。本节是品牌规则唯一权威，品牌资源不计入架构图册。

<a id="speech-prototype"></a>
## 当前语音验证与主人识别

当前 [speech_probe.py](../tools/speech_probe.py) 仅处理显式文件：本地生成一段中文语音，转写生成音频与供应商示例，提取声纹特征并运行 VAD。输入限定 PCM16 单/双声道、8—48kHz、最多 15 秒，转为 16kHz；声纹要求一维、192 维、全为有限值且范数非零，显式传入文件的转写也必须非空才能通过。模型选型和资源参数由[本地模型页](models-offline.md#configured-models)维护。

没有自动开启麦克风，没有播放或上传个人录音，没有保存主人声纹档案。声纹向量能计算不等于能识别主人，更不代表防录音重放或合成声音攻击。当前报告固定 `owner_enrolled=false`、`voice_authentication_granted=false`。

后续按授权登记多段主人语音，再用不同距离、噪声、麦克风、非主人、重放和合成语音样本校准阈值，统计误接受与误拒绝。声纹用于“更像哪位说话人”的辅助判断；关键授权仍采用[独立身份入口](security-sovereignty.md#identity-authorization-2)。当前预置 TTS 不是朋友声线克隆，8kHz 语音也不代表最终自然对话质量。实时打断、回声消除、持续会话与人格一致性尚待实现及 M2 验收。

### 语音聊天与多人识别接入计划（2026-10-18）

**0.1.81 已接通显式开启的连续语音：自动分段、本地识别、同一会话发送、朗读后继续监听；保留 0.1.80 按键预览。** 原[手动朗读](#chat-readout-ui)与[Qwen 主力](models-offline.md#qwen-tts-runtime)继续使用；识别组件与资源上限归[本地 STT](models-offline.md#speech-input-runtime)，验证范围归[本轮证据](delivery-validation.md#k6-voice-input-evidence)。连续轮次与受限插话见[新增证据](delivery-validation.md#k6-continuous-voice-evidence)；物理回声消除、语义轮次判定和多人声纹仍待验证或实现，不能宣布完整 K6/M2 通过。

输入框右下角麦克风 → 点击录音 → 再点结束（最长 20 秒）→ 检查/编辑预览 →「填入消息」→ 使用原发送键。原有草稿会保留，转写追加在其后；切换会话、页面隐藏、取消或设备断开时停止采集并丢弃本轮输入。权限拒绝仍可打字。静音或无法识别时说明原因，不生成默认指令。

展开「语音选项」可选择语言、启用「自动朗读本页的新回复」。开关默认关闭、刷新复位，只处理新发消息的完整成功回答，不读历史恢复内容；新录音或新消息停止旧播报。浏览器阻止自动播放时沿用朗读面板的“点击播放继续”，不绕过权限。录音不会上传模型；主人检查并发送后的文字按当前会话模型路由处理。识别无额外云模型费用，聊天费用仍依原模型。

耳机图标打开语音选项 →「开始连续语音」。开始前显示会发送转写文字到当前模型；开启后收起选项，保留状态、结束按钮与播报时的「我要插话」。默认在回复与播报期间丢弃输入样本，轮到主人时自动检测片段；后台任务保持独立。「自动检测插话」默认关闭，建议耳机环境实验：候选语音先暂停播报，本地识别为空、简短附和或与当前回答完全匹配的片段时继续原位置；识别到新请求则结束旧播报并进入新轮次。「停一下 / 停止朗读 / 别说了 / 暂停 / stop / pause」只停止播报并回到监听，不取消后台任务。附和与文字回声判断是有限启发式，不是主人识别或声学分离证明。

连续语音复用原会话人格、已授权记忆与历史，但自动轮次只允许交流：后端禁止个人指令提交与 WorkAdmission，前端不继承文件生成模式、显式技能与待发送附件，不消费键盘草稿。需行动时退出连续语音，检查文字并从原入口发送。当前项目/通用记忆隔离、临时会话与云端路由规则保持；转写文字在普通会话中保存，临时会话不持久化。停止、隐藏页面、换会话或设备断开会释放麦克风，取消所属识别/对话并拒收迟到输出。失败不会自动重新发送；原文字聊天继续可用。

每次最长 10 分钟、20 个发送轮次、40 个识别片段；连续安静 60 秒或 8 次没有新请求后退出。单段达到 18 秒上限时展示转写但不自动发送，避免把被截断的话当完整指令。普通轮次停顿约 1.1 秒即分段，犹豫/长停顿可能拆成多轮；这些默认值和实验模式不替代真实交谈验收。麦克风会话期间浏览器音轨保持开启，等待回复/默认播报时仅丢弃样本，不宣称系统麦克风已关闭。静音等待不调用模型或轮询 ASR；语音识别在本机，自动发送文字仍按当前模型计费。

当前输入区麦克风显示录音状态、识别语言与本地处理来源；说话人状态和云端来源提示随对应功能以后加入。打开设置不录音；拒绝权限、设备拔出或识别失败保留文字入口。后续自动轮次与打断沿[唯一语音链路](#interaction-tasks-2)扩展，图标/悬停/聚焦提示与无障碍名称遵守[现有规则](#workbench-settings)。

声纹、语音分段和声音克隆是三个独立入口：身份样本经主人明确登记后形成可删除的本机档案；分段先显示匿名说话人，再匹配登记人，未知人不自动命名；克隆需要单独的参考声音与授权来源，不能拿身份向量还原成声线。原始录音默认仅保留当前轮处理所需缓存，不自动写入文字归档或长期知识，云端外发按实际目的地说明。单靠声纹不能授予高风险动作，重放/合成声与跨语种误判须单独测试。

播报按有界短句进入播放队列；新一轮录音和停止动作先停止/清空旧播报，丢弃旧 turn 的迟到音频，不重新提交已完成任务。浏览器 AEC/降噪设置只是请求，不能当成真实声学消除已通过；首版按键录音暂停播报以减少自听回声。语音识别、TTS 和播放有独立取消与预算，后台任务仍沿原队列运行。资源不足时依[候补规则](models-offline.md#voice-routing-policy)只替换需要的环节，偏好与人格身份不因此改变。

#### 聊天回复朗读（0.1.45 工作树）

**implemented，有限真机链路 verified。** 每条助手回复下方提供带文字提示和无障碍名称的喇叭图标，点击后才按需加载本地 Qwen 并朗读。输入区上方显示当前分段、暂停/继续和停止；“朗读选项与内容”可选择音色、默认表达和语言，填写表达提示，编辑正文或插入已有分段标签，再点击“按此内容重新朗读”。修改选项不改变已经生成的音频。展开选项使用可滚动浮层，避免把输入和发送按钮挤出普通 PC 屏幕。

播放器逐段连续播放，暂停保留当前位置；选择另一条回复先停止旧朗读，切换会话或关闭页面也停止。停止朗读不取消文字生成或后台任务；设置页可观察主力被聊天朗读占用，并独立停止组件。正常播放结束保持模型就绪，中断正在加载或合成的组件后，下次可能重新加载。

代码块和网址在朗读准备阶段略过，超长正文明确提示缩短，不静默截断；普通说明中的未知方括号文字按正文处理。清洗与分段限额归[朗读接口](contracts.md#chat-readout-contract)。音频保存在本机语音目录，**临时会话朗读也会生成音频文件**；当前没有新增音频自动清理器。页面持续提示这一点，不把临时文字归档语义扩大到生成音频。

这是文字回复的本地朗读；0.1.80 已接入[按键语音与新回复播报](#voice-chat-plan)，声纹与全双工仍未完成；实际性能和并行范围见[联测证据](delivery-validation.md#chat-readout-evidence)。

<a id="interaction-tasks-1"></a>
### 五条执行通道

界面区分控制、语音、对话、正式工作、维护五类活动，显示各自运行/排队/等待资源/不可用状态。正式任务进度显示在任务卡，前台继续接收交流；原型当前只实现其中部分。唯一通道与调度定义见[普通 PC 并行规则](tasks-agents.md#conversation-resource-isolation)。运行恢复和未来独立监督属于[架构控制边界](architecture.md#current-runtime-topology)，不因为本次对话改造而声称已经部署。

<a id="unified-conversation-experience"></a>
#### 打字与语音共用一个交流入口

**proposed。** 用户无需先选“任务/闲聊/情感”模式。发送文字或提交语音最终转写后，界面立即显示本轮受理状态，保持输入区可用；需要工作时插入关联任务卡，当前回复不等工作完成。保留已有明确任务指令作为可预测的兼容入口，自动分流后的用途可展开查看和纠正。纠正只修改相关任务/回复，不能重置整段交流。

语音先接入“按键录音 → 本地转写 → 可编辑发送”；通过该链验证后，再开放显式开启的连续对话模式，由轮次判断自动提交最终文本并自动播报短回复。连续模式开始一次会话后不要求每句话点击，关闭即停止采集。输入区可同时打字；打字发送属于新输入，草稿不被晚到转写覆盖。录音权限、设备故障和识别失败只影响语音，文字入口保持可用。

收到新输入不等于任意并行说多段话。补充当前要求、修正上一句、新话题由轮次协调器处理；相同交流流只呈现当前有效回复。原回复迟到的文字和音频不得插到新回复后面。用户明确说“你继续做，先回答我这个”时，新对话不自动取消正在执行的工作。

工作完成默认更新卡片和未读提示，在当前一句说完后选择合适时机简短提醒；倾诉或紧密对话时避免插播普通进度。可以明确设置某项工作完成后立即通知。任务细节和中间日志不灌进聊天；个人记忆与工作资料的范围沿[记忆管理](#memory-domain-ui)。

停止控制清楚区分“停止播放”“停止本次回复”“取消指定任务”“关闭语音”。含糊的“停一下”先静音当前播报，随后核对所指对象；不会取消所有后台工作。界面显示的是实际状态，模型尚未确认受理时不能先显示“已开始执行”。设置中复用模块/资源面板显示识别、回复、合成与任务各自延迟及瓶颈，不把一次模型慢响应显示成整个 Jarvis 离线。

<a id="dialogue-intent-shadow-ui"></a>
#### 查看本轮理解、文档草稿与自动任务（0.1.57）

普通回复下方的“意图参考”可显示闲聊、问答、情感交流、任务、控制、记忆/偏好等多个片段，并标出当前请求、讨论/引述/假设、明确否定或缺少的信息。0.1.57 对通过[限定准入规则](tasks-agents.md#conversation-intent-routing)的单项文档请求自动受理，显示“任务已受理”、独立任务回执与“查看真实任务”；不再重复提供草稿按钮。后台完成后可查看文档结果和下载调用回执，刷新保留任务链接且不重跑。其他识别结果显示“未自动派发”，不代替实际任务状态。

识别到完整的软件库文档需求时，可点“准备文档查询草稿”。程序检查当前会话/项目、Context7 策略和连接后，将库名、问题放到现有文档工具输入区；已有草稿、附件、进行中输入或会话变化均不会被覆盖。检查草稿后点击发送，才沿原任务队列执行；仅准备时不调用 MCP、不额外调用模型。普通会话刷新后保留简短识别摘要，详细卡不保证永久保留；原回复可恢复时可随回执取回。

识别格式失效时保留可用正文；只有破碎协议时显示未完整确认，禁止当成文件正文自动保存。宿主 4 KiB 指令预算或模型输入预算不足可跳过识别，继续普通回答，不追加付费重试。设置页 Context7 卡片与详情说明当前开放条件，选用规则可设为仅明确指定或停用。协议与限额见[意图契约](contracts.md#dialogue-intent-shadow-contract)，效果及限制见[实测证据](delivery-validation.md#dialogue-intent-shadow-evidence)。按键录音已见[语音交互](#voice-chat-plan)；连续轮次已接入；物理全双工与通用自动行动仍在后续范围。

<a id="mixed-report-ui"></a>
#### 边聊天边生成、修改和取消样例报告（0.1.59）

普通已保存会话选择 Google Flash，可说“我很难过，陪我聊聊，顺便把样例报告导出。”自然回复与后台任务分开显示；成功受理时出现“任务已受理”和真实任务链接。目录范围、进度和产物来自账本，任务执行期间可以继续交流。

- 指定子目录：`导出样例报告 目录: sub/data`。这里是已配置样例根内的相对目录，当前项目不会改变范围。
- 修改尚未开始的报告：在“本会话任务”点“修改目录…”，填好相对目录再发送；也可输入 `把报告 task_完整编号 的目录改为 sub`。已有草稿不会覆盖；原任务保留取消记录，详情显示新目录及替换对象。
- 仅取消一项：`取消报告 task_完整编号`，或使用原“取消任务”按钮。已完成结果不会因取消消失；取消回复和取消后台任务仍是两件事。

含糊指代、参数未确认、临时会话、附加要求及其他模型不会由此自动派单；可改写明确要求或使用现有任务模式。完整规则只维护于[统一意图受理](tasks-agents.md#conversation-intent-routing)，实测和仍存在的漏受理见[验证记录](delivery-validation.md#mixed-report-admission-evidence)。

<a id="dialogue-receipt-ui"></a>
#### 已实现的文字待发与独立停止（0.1.48）

当前普通文字回复期间输入框和发送按钮继续可用。后续文字进入“待发送”区，**尚未发送给模型**；最多 4 条，每条 16 KiB，仅保留在本页，关闭或刷新会提示尚有活动内容。下一条等上一条实际结束，再使用更新后的会话历史；不把输入解释成修改当前任务或插话。正在编辑的另一个草稿不会被自动发送覆盖。

待发消息可在输入框为空时移回编辑；满额时保留原草稿。上一轮失败、结果不明时暂停待发，由用户点击继续；没有自动重发上一条。待发暂限普通文字，不含附件、文件生成和个人/成长指令；项目与会话在有待发项时锁定，避免内容移到其他范围。

“停止回复”单独显示，停止采用当前输出并查询实际收尾，**不取消后台任务或现有朗读**。收尾期间可继续排入文字；`/任务`、`/进度`、`/取消` 仍走原任务入口，控制消息不纳入普通模型历史。任务面板与待发区各有滚动上限，给聊天正文留出空间。已有语音仍为点击回复后朗读；完整自然语言分流、语音输入与打断仍按[统一交流设计](#unified-conversation-experience)实施。

接口与限额权威在[回复回执契约](contracts.md#dialogue-receipt-contract)，实测在[分离验收](delivery-validation.md#dialogue-receipt-evidence)。0.1.49 补充下面的恢复入口。


<a id="dialogue-recovery-ui"></a>
#### 刷新后查询与取回原回复（0.1.49）

0.1.74 对已经结束的恢复记录增加“收起此提示”，仅在本浏览器会话隐藏该提示，不删除原回执、费用或聊天，也不补发 UNKNOWN。

打开原普通会话时，根据已归档的 `reply_ref` 查找尚未取回的回复，最多展示最近 8 条。进行中的回执在页面可见时继续查询，亦可独立停止；已经完成的显示“取回回复”。点击后将原回复追加到本会话并保留关联，避免再次刷新重复插入，也不覆盖正在编辑的草稿。

恢复不会重新运行模型/个人指令/任务，不自动写文件或播放语音。恢复文字可以按已有入口另存或朗读；带附件的旧输入不能假装附件已经恢复。只有当前最后一条未配对的普通输入，才将完整恢复结果加入当前模型上下文；更早的恢复结果保留可见，避免把迟到旧话串到新话题。追加不移动既有消息，保护记忆和接续的来源索引。

Host 重启时未完成请求显示“结果未确认”，提供查询而非自动重做。已过期、未受理、临时会话或已删除记录不会凭空恢复；失败不显示已完成。待发队列、未发送草稿、附件仍仅本页保留，刷新不保存它们。临时会话不写恢复表；普通会话删除同步清除关联恢复正文。

完整保留策略在[持久恢复契约](contracts.md#dialogue-recovery-contract)，验证在[恢复验收](delivery-validation.md#dialogue-recovery-evidence)。

0.1.51 后普通对话的模型等待由按需进程承担。“停止回复”会回收此次本地模型调用进程，后台任务仍保留自己的停止入口；模型进程异常会报告结果未确认，不自动重新花费用量。之后可以发送新请求。设置 → 模块与升级 → 并行运行与延迟增加[对话模型进程状态](health-maintenance.md#dialogue-runtime-monitoring)，个人资料指令和精确计算仍可直接由 Host 完成。

0.1.54 将普通上下文准备也纳入该进程，并增加独立的“后台模型进程”卡。可分别看到对话与目录/技能/REA 解释正在准备上下文还是等待模型，结束后槽位回到空闲。后台报告用任务卡取消，普通回复用“停止回复”；两者互不代替。具体范围与剩余限制见[分槽验证](delivery-validation.md#conversation-lanes-evidence)。


<a id="interaction-tasks-2"></a>
### 语音链路

```text
麦克风 → 回声/噪声处理 → 按键或 VAD 与轮次判断
        → STT 适配器 → 最终转写 → 统一会话受理
        → 对话回应与可选任务分支 → 短句表达规划 → TTS → 播放
打字 ──────────────────────────→ 统一会话受理
```

云端实时语音作为另一种可替换实现；本地文字和基础语音应保留。轮次与打断机制可参考 LiveKit，但本地单机路径不能隐含依赖云服务。[S19](references.md#s19)

首版复用已选的 SenseVoice int8＋VAD；它是对切段音频做非流式识别，不能把麦克风持续采集称为模型原生流式 ASR。需要稳定中间字幕时，再对比真正流式后端；部分识别用于显示和推测，不据此提交现实任务。端点静音长度须按中文、英文、犹豫和停顿样例调优，VAD 不等于语义轮次结束。[具体依据](references.md#conversation-isolation-sources)

连续模式在播放期间仍处理输入。疑似插话先停止/压低播放，再结合识别判断是新要求、附和还是回声；误打断的恢复只恢复原音频剩余部分，不重放任务。每次播放绑定 turn/generation，取消后立即清空客户端音频队列，并取消对应合成；没有合作式取消能力的组件单独终止/重载，不能顺带停掉所有任务。只将已实际播放的片段记为“已播报”，全文可以留在屏幕，不假设用户听到了未播部分。

Qwen 继续承担已选的自然度与情绪表达，语气按句/短段规划，任务日志不朗读。现有分段 WAV 是可复用基础，不是端到端音频流；先缩短首段、按预算预热、在前段播放时生成后段，再考虑原生 PCM 流输出。实测约 9.34 秒的冷启动需单列，不能用后续热合成耗时替代。资源与候补仍遵守[语音路由](models-offline.md#voice-routing-policy)。

“停一下”优先立即停止当前播报，再根据上下文判断暂停当前任务还是全部任务；含糊时不擅自取消所有工作。机械设备紧急停止通过设备底层入口处理。

<a id="persona-embodiment"></a>
## 人格、性别表达与具身形态的开放扩展



<a id="persona-embodiment-1"></a>
### 人格是可组合的能力配置

主人可以用自然语言定义严谨、幽默、温柔、活泼、简洁等个性，以及男性、女性、中性或自定义的性别表达，设置朋友、伴侣式伙伴、管家、教练、研究搭档等关系模式。系统将要求编译为可预览、可版本化、可回退的配置。

性别在这里指声音、称谓、形象与表达方式的模拟，不意味着系统具有人的生理性别。关系设定不能隐式扩大权限或改变 G0。

| 层次 | 内容 | 变更规则 |
|---|---|---|
| 主体身份 | 主人绑定、共同体身份、根原则引用 | 不由人格或角色工厂改写 |
| 人格表达 | 语言、语速、幽默、温柔程度、主动性 | 可按主人要求调整和版本化 |
| 性别表达 | 声音、称谓、外观和自定义呈现 | 与能力和权限独立 |
| 关系模式 | 伙伴、管家、教练、伴侣式陪伴等 | 改变交流方式，保留真实系统身份 |
| 具身形态 | 文字、语音、桌面角色、2D/3D 化身、NPC、实体机器人 | 经对应形态适配器实现 |
| 能力范围 | 工具、知识、设备、网络和行动权限 | 由独立授权与 G0 门禁控制 |

<a id="persona-embodiment-2"></a>
### 切换与连续性

基础的文字人格和连续相处属于 K2 核心；声音、复杂化身和实体具身按 K6 逐项扩展。PersonaProfile 管表达、称呼和关系配置，Memory 管有来源的偏好与经历，Task Runtime 管实际承诺与执行状态；三者引用关联，不用一段不断增长的角色提示词替代。当前会话要求影响本轮表达；0.1.39 的持久表达子集如下，完整多配置 PersonaProfile 仍为设计目标。

1. 同一主体可以保留多个配置，也可以在不同终端使用不同表达。
2. 主人可预览若干对话和表情场景，再激活或回退；已有授权允许按情境自动选择配置。
3. 正在执行的任务、动作状态与真实记忆不随角色切换丢失。
4. 人格版本在轮次或会话边界切换，不在一句话中途更换声音或关系设定。
5. 同时存在的工作人格与陪伴人格通过独立会话处理，不能对同一设备发出冲突指令。
6. 自我改造可以优化表达，但不能擅自改变主人设定的关系边界，或以提高黏性为目的操纵主人。
7. 真实人物模仿属于获授权的表达近似，不承诺复制其内心、身份或全部反应。

<a id="persona-runtime"></a>
#### 基础人格运行范围（0.1.39）

**implemented；分项验证见[个人核心证据](delivery-validation.md#personal-core-evidence)。** 独立 [persona.py](../runtime/node-host/jarvis_core/persona.py) 在运行数据目录保存 `persona.db`，保存受限称呼、固定交流风格、相处方式枚举、当前/上一版及请求回执。它不保存任意 system 提示词、主人身份、事实正文或动作权限；不调用模型生成配置。

一轮普通聊天开始时读取一个修订快照，候选路由切换沿用同一快照，下轮才采用新设置；新会话与重启沿用已保存配置。Host 将枚举转换为固定表达提示，并说明当前用户要求优先、权限和真实性不变。改变关系不会创建执行任务或改动记忆。撤销在当前/上一版间切换并生成新修订，不假装回到旧历史状态；不是无限版本备份。存储损坏时聊天可退回默认表达并显示原因，不能静默覆盖损坏文件。

0.1.62 已支持受限称呼；当前没有性别表达、声音、化身、多个并存人格或自动情境切换；也不能凭风格提示保证每个模型都达到理想的陪伴效果。接口和容量归[个人核心契约](contracts.md#personal-core-contract)，操作语法归[聊天指令](#personal-core-ui)。

<a id="persona-embodiment-3"></a>
### 虚拟机器人与实体机器人分开

机器人外形、机械音或虚拟动作属于呈现适配；实体运动、摄像头、抓取和导航属于设备能力，必须由动作网关和设备控制器处理。

同一句“跟我来”，在 NPC 世界中是模拟移动，在桌面化身中可能只是界面动画，在实体机器人中则必须经过环境与设备能力检查。形态配置不能自动把虚拟权限转换为现实权限。

<a id="persona-embodiment-4"></a>
### 配置与接口

```yaml
persona_revision:
  profile_id: companion_custom
  version: "3"
  subject_identity_ref: jarvis_owner_subject
  style_traits: ["warm", "concise"]
  gender_expression: owner_defined
  relationship_mode: companion
  voice_ref: voice_local_v2
  avatar_ref: avatar_robot_v1
  memory_namespace: owner/private
  activation_scope: session
  root_principle_ref: G0
  authority_policy_ref: owner_policy_current
```

人格配置只引用原则和授权，不携带修改它们的权力。建议接口为 compile、preview、activate、rollback；形态适配器提供 describe_capabilities、present 和 observe。

## 成长中心：自检、自愈与进化

**0.1.64 已在设置 → 成长中心接通限定对象的三标签及用途设置，implemented。** [设计预览](prototypes/growth-center/index.html)保留为完整交互目标，不连接运行 API；下面的完整抽屉、深度检查和实验比较是目标方案，当前已实现范围见[线上入口](#growth-center-current-ui)。

<a id="growth-center-layout"></a>
### 页面结构与三个标签

设置侧栏提供一个“成长中心”入口；“模块与升级”继续承担组件清单、本地组件启停和运行包维护，避免把观察面板、工具演示与安装器堆在同一页。成长中心固定结构为：标题与总状态 → 三个横向标签 → 当前能力的简洁动态状态区 → 核心工作区 → 最近事件。聊天工作台不新增占据输入区的永久卡片。工作台若增加直达入口，遵守[顶栏图标规则](#workbench-settings)，不另写规则。

| 标签 | 首屏主要内容 | 主操作与次操作 | 右侧可关闭策略面板 |

| 自检 | 当前检查范围、覆盖/未覆盖、最后完成时间与过期状态；异常优先展示 | 立即自检；快速/深度、查看证据、暂停周期项 | 事件与兜底周期；是否启用 AI 辅助诊断；专属模型和档位 |

| 进化 | 主人目标、待评估机会、当前实验、新旧能力与代价对比 | 新建改进目标/开始所选实验；查看差异、停止实验、回退 | 自动提案/研发/发布各范围、空闲与预算条件；专属模型和档位 |

状态区控制在约 180—240px 高，不用巨型 Logo、长篇规则或无实际依据的健康总分占满屏幕。优先表达“什么正在发生、影响什么、下一步是什么”；不显示虚构倒计时、算力百分比或情绪指标。无异常时自愈页面显示安静待命，无进化任务时显示目标入口，不伪造后台持续工作。三个标签保留各自筛选、滚动位置和草稿；有保存更改前的脏状态提示，切换标签不覆盖另一用途配置。

桌面工作区用主内容与右侧策略抽屉，默认约 400px，宽度可拖拽并有键盘调节，受视口限制；关闭后主内容恢复宽度。窄屏抽屉成为单独的完整设置视图，有明确返回按钮，不挤成三列。标签使用 tablist/tab/tabpanel、方向键/Home/End、焦点可见；右上图标具备 tooltip 和无障碍名称，关闭抽屉后焦点返回原入口。费用、异常和可用性同时用文字与图标表示，颜色不是唯一信号。

<a id="growth-center-motion"></a>
### 保留 J 标志，用状态驱动科技感

整体采用深石墨背景、有限的柔光与细线结构，保留既有机器轮廓和 J 标志；不用新圆形机器人替换品牌。三标签共享视觉骨架，但动画有明确语义：

| 状态 | 动效 | 收束与无动画表达 |
|---|---|---|
| 待命 | J 标志外围极轻的 6—8 秒呼吸光；鼠标移入边缘微亮，离开平稳复原 | 主体保持清晰静止；文字显示待命，不靠永久转圈暗示工作 |
| 自检运行 | 青色扫描线经过模块节点；已检查节点按真实阶段依次点亮 | 仅播放已收到的阶段；结束后停留证据摘要，未检查部分保持未覆盖 |
| 自愈运行 | 琥珀色断点标识受影响区，已有轮廓片段向接缝合拢，复测成功后连线恢复 | 未通过时接缝不合拢；回退沿原路径反向收束；等待不播放成功效果 |
| 进化运行 | 紫蓝色新分支在原结构外围生长，候选与现有版本分别显示，验收后建立正式连接 | 候选是候选，只有发布确认后才并入主体；拒绝分支淡出并保留记录 |

标签转换约 180—260ms；阶段演示约 1—2 秒，不用动画拖延真实操作。默认无音效，未来若有声音必须遵循现有声音偏好，不能每次后台巡检响一次。CSS transform/opacity 与有限 SVG 线段足够，首版不加入 Three.js、粒子引擎或持续全屏 Canvas。隐藏页签、不可见区域、暂停动效或 prefers-reduced-motion 时停止装饰动画；减少动态模式仍显示文字、阶段和静态图标。动效不得阻断聊天、取消、点击和键盘操作。

### 将验收代码变成可重复使用的项目工具（0.1.76）

在已保存项目会话中打开已验收的编程结果，选择“纳入项目工具”，填写工具标识、名称、适用及不适用说明，核对准入依据和灰度预算，再选择“审阅并进入灰度”。同一标识的新产物是待升级候选；原稳定版继续使用，新工具尚未启用。旧验收继续保留，项目源文件仍由原“应用/恢复”入口管理。

右上角“项目工具库”遵守[顶栏图标规则](#workbench-settings)。点击在可关闭、可调宽度的右侧工作区打开工具列表；同项目其他会话也可使用。每项显示状态、保留案例和用量，支持 JSON 输入、可选独立预期、运行、停用和复验恢复旧版。结果显示“执行完成”或“结果与独立预期一致”，避免将两者混为一谈。

活动任务面板查询本机回执，不触发模型请求。取消只作用于当前工具任务；刷新与核对不会自动重放未知请求。页面刷新后可重新打开目录查看原记录。无已保存项目会话时提示先选择项目；不要求为了普通闲聊建立工程。

0.1.77 的全局容量入口位于设置 → 成长中心 → **成长账本与容量整理**，默认折叠，点击“预览引用与容量”才读取资料。面板明确显示所有项目的范围、在线/归档数量、不可整理原因及最近整理回执；选择记录、填写依据并核对后才归档，界面不按年龄替主人勾选删除。响应丢失先刷新核对原整理回执；按原任务编号仍能查看完整结果。目录收存/恢复分别操作，恢复后仍退役，工具卡提示到容量入口恢复目录，禁用旧的直接回退按钮。窄屏允许记录区纵向滚动。行为与配额只归[容量治理](evolution-release.md#growth-ledger-maintenance)和[接口](contracts.md#project-tool-contract)。

0.1.75 在工具卡片中显示灰度/暂停/正式启用/拒绝/退役状态，独立新输入、用途反馈和次数预算。填写本次 JSON、独立预期并勾选核对，说明用途及依据后“灰度试用候选”；保留案例和重复输入不增加准入数。达标后“核对后正式启用”才可用，并仍需明确操作依据。观察详情折叠显示配对耗时、旧版正确性、审阅和版本；证据不足时不提供夸大的收益分数。

同一卡片提供暂停、继续、放弃、能力退役和旧版本退役。退役后运行/旧恢复不可用，“重新准入退役能力”只回到新的灰度，不能直接恢复调用。重启暂停原灰度，不自动继续；输入/用途/审阅草稿在当前打开面板刷新时保留，整页刷新后以已受理回执为准。完整状态与保护规则归[生命周期](evolution-release.md#project-tool-lifecycle)，检查记录见[本轮证据](delivery-validation.md#k4-lifecycle-evidence)。

0.1.76 新候选卡片有折叠的“契约体检”：公开/留出和不同输入计数、已观察形状与待核对问题；明确显示“业务正确性仍需审阅”，没有模型自评高分。顶部容量摘要区分全局在线包、已归档数量、回执名额与 SQLite 可复用页。

“旧版本归档与在线容量”折叠区列出退役和归档版本，复用本卡片的操作核对与依据，提供“核对并归档版本”和“载回为退役版本”。受引用版本即使出现在退役列表中，后端也会拒绝归档；失败保留材料和原回执，不自动删除或重试。成功后刷新真实数量并显示中文结果、启用状态与材料保留情况；载回不会显示成已启用。规则与限制统一见[体检和归档](evolution-release.md#project-tool-quality-storage)，[本轮验证](delivery-validation.md#k4-quality-storage-evidence)。仍使用同一个可调宽度的右侧工具库，不新增顶栏文字入口。

0.1.72 增加“按需求找工具”，在同一右侧工作区打开“工具需求”标签。已经发布名为“求和工具”的工具后，在聊天输入 `请用求和工具处理 [10,20]` 可直接取得实际结果；输入 `/工具 整数列表求和` 先看候选，再填写本次 JSON 和可选独立预期。`/工具 请把温度转为华氏度` 若未匹配，会显示“补齐验收并建立编码改进单”；点击准备原有编程表单，原需求持续关联，不直接开始付费编码。

分析结果、调用结果和编码状态分别显示。聊天保留“查看改进与结果”，刷新后可打开原需求而不重新执行；取消只影响该需求的实际任务。“按当前目录重新分析”建立新分析，并等待选择，不能自动重放原调用。填写中的选择、JSON 和预期在面板刷新时保留；它们是当前打开面板的草稿，关闭面板或整页刷新前应自行保留，尚未持久化为任务。未知请求优先“刷新与核对请求”，不会自动重发。后台执行沿用成长通道，聊天无需一直等待。

0.1.73 在未匹配需求卡片上增加“验收草案与审阅”，仍使用可关闭、可调整宽度的右侧标签，不新增顶栏文字按钮。点击“生成验收草案（调用进化模型）”会按成长中心进化设置发起模型请求；模型与备选设置可直接打开。生成中可取消，未知响应先刷新核对。

草案表单分别展示输入、输出、不包含的能力、公开案例和待澄清问题。补齐答案、独立留出案例及依据，勾选核对后点击“使用已核对草案准备编码”，会填入原编程表单；再核对源码路径、模型和构建方式并发送，保存审阅和待开始改进单。公开案例在编程表单中改动后须回草案同步核对，不能静默改变已审阅契约。审阅冻结后表单只读，“核对或继续原编码交接”复用原内容；完整契约在成长进度中折叠展示，标题保留原需求。未提交的表单草稿只在当前面板刷新时保留，关闭或整页刷新前应先自行保留。

普通聊天不要求打开项目；新增工具入口只在已保存项目会话使用，普通无 JSON 的文字表达继续走聊天。规则与当前边界见[运行权威节](evolution-release.md#project-tool-runtime)和[需求选择](evolution-release.md#project-tool-intents)，验证见[本轮证据](delivery-validation.md#k4-tool-intent-evidence)。


**0.1.78 可持续成长入口：**项目工具库 →「可持续成长」，或聊天 `/工具` 的缺口记录 →「按限定契约持续成长」。仍使用可缩放、可关闭的右侧工作区，不占用聊天输入区。先选择受支持的契约并保存项目成长策略，再开始一轮；进度展示编码、正常对照、灰度、启用观察和停止原因。策略模型沿用现有模型目录，刷新只查原回执，取消与恢复记录持久保存。费用/token 未知显示未知，未提供主人体验反馈不显示“满意”。规则归[成长策略](evolution-release.md#bounded-growth-policy)。

### 模型、备选和费用怎样设置

每个标签的“策略设置”打开同一组件的独立用途实例：首选模型 + 原生档位，下面是可增删和排序的备选列表，每个备选有自己的档位、适用状态与连接标识。模型选择自动对应供应商，不再先选供应商。目录无该档位时禁用并解释；页面同时显示“请求档位”和适配后“实际参数”，不把深度预设当成所有厂商相同的算力等级。高级项允许为诊断、编码、评审单独覆盖；默认继承，不强迫用户填写九套模型。

三个档案分开保存，保存时核对配置代际；运行任务继续使用冻结配置，提示“用于下一次任务”。策略面板有触发方式、范围、预算提醒/硬限制与备选切换规则；完整行为只维护在[模型用途路由](models-offline.md#growth-model-policy)。一次故障切换显示“首选 → 备选、原因、实际模型/档位”，而不是仅把下拉框悄悄换掉。用量区区分本地检查 0 token、云端实际回执、未知用量与估算费用。

“模拟切换”只验证配置路径，明确不真实调用；“测试连接”是独立显式操作，事前说明会产生请求。列表可读不代表模型可调用、仍有余额或质量合格。将不兼容/无证据模型列为待验证，而不是假装所有选项都适用于所有任务。

### 当前线上入口与迁移状态

0.1.64 的入口为 **设置 → 成长中心**（`/settings#growth`），总览有直达卡片；“模块与升级”保留组件与运行包管理。自检、自愈、进化三个真实标签分别显示范围、动作和记录；支持方向键/Home/End。保留现有 J 标志；待命呼吸、自检扫描、自愈轮廓合拢、进化轨道动效由真实任务状态驱动，后台页和减少动态偏好下暂停。

当前每页内嵌本用途主模型、一个备选和合法原生档位，三个用途草稿同时保留，一次保存整个策略并核对修订；尚未实现可拖拽策略抽屉、多备选排序或各用途分开保存。周期自检、自动自愈各自开关；进化由明确需求启动。修改后有未保存提示，运行按钮等待保存；轮询不覆盖草稿。任务只返回真实状态，回执/候选源码在折叠区，模型输出按纯文本显示。旧混合检查单明确标历史。打开页面不调用模型。

原三用途设置管理文件清单导出配方；项目工具成长保留项目内入口。0.1.79 在“进化”标签下增加“自身模块改造 · 检索排序”，与原模型策略草稿分开，编辑它不会误触发原设置未保存状态。自动维护规则引用[原成长运行规则](evolution-release.md#bounded-evolution-loop)，不在 UI 另设授权通道。

### 检索模块生成、试用与回退

入口为**设置 → 成长中心 → 进化 → 自身模块改造 · 检索排序**。先选择本次编码模型，点击“生成候选并独立评估”；展开记录可查看完整源码、独立案例、耗时、已知失败与模型实际用量。通过限定准入后填写审阅依据，点击“审阅后试用”。按钮明确区分“生成”“试用”“保留”和“恢复内置排序”，不能把评估结束显示成已启用。

当前版本、试用标志、不同查询样本数和最后恢复原因持续显示。少于 3 组有效查询时不能保留试用；刷新后从服务端取回原状态。生成响应中断先核对原请求；尚未确认的试用在宿主重启后回退，页面刷新本身不会回退。当前操作的范围、协议和限制分别引用[生命周期](evolution-release.md#ranking-module-growth)与[契约](contracts.md#ranking-module-contract)。

详情默认折叠，不把源码、评测表和运行编号放到普通聊天输入区；仅任务运行且面板展开时刷新进度。沿用既有三标签布局、键盘访问和窄屏换行。这个入口没有新增顶栏文字按钮，顶栏规范仍以[唯一规则](#workbench-settings)为准。

## 协作分析入口（0.1.82）

在对话输入框上方“普通对话”下拉框选择 **协作分析 · 方案与审阅**，展开“协作分工与检查要求”，分别选择方案/审阅模型和推理级别，填写检查要求，再发送任务。无需创建项目；适用于学习、生活安排和工作方案。检查项为空时保留草稿，不调用模型。

页面明确告知只分享本条任务、检查项与候选方案，临时会话也会保存任务；没有自动执行、记忆写入或重试。刷新依原任务编号恢复查询；切换会话关闭旧报告并清空旧检查要求草稿，防止错看或混用另一个会话的资料。无新增顶栏文字入口，[顶栏图标规则](#workbench-settings)保持。全部额度与停止语义见[协议](contracts.md#team-analysis-contract)，不在本节维护第二份规则。

## 设备与共享入口（0.1.85）

在**设置 → 设备与共享**管理本机身份、按需监听、配对和共享资料卡。身份区显示指纹；连接配置默认折叠。先在共享端打开监听并创建配对码，再到加入端粘贴，完成后新建资料卡。共享端等待加入端点击“立即双向同步”，双方资料在该次交换中收发。没有自动后台轮询或默认联网。

空间选择器区分等待配对、待确认、已配对、已撤销；待确认时显示“重试原配对”。卡选择器标记冲突或已删除，冲突文本以折叠的两份版本呈现，主人在编辑区合并。所有外来文本按纯文本显示；不执行 HTML。刷新和同步保留未保存草稿与原修订摘要，过期保存拒绝覆盖；切换卡或空间前询问是否放弃草稿。

0.1.84 增加“导出资料副本”和“预览空间归档”，预览显示卡数、大小与撤销效果，再由主人确认。下方“已归档空间”提供导出与只读恢复；恢复自动显示首张卡，正文可选择复制、不可修改。异常状态单独显示“检查恢复范围”，关闭监听后预览、保留原件并恢复只读内容。各按钮明确区分保存内容与恢复连接，不宣称能找回旧备份中没有的数据。

“模型使用授权 · 仅本机”独立显示当前空间的用途、卡选择及模型接入方选择。新空间默认全部关闭；用途选择个人聊天或一个具体项目。保存和撤销有独立按钮、版本回执；未保存选择在切换空间前提示，过期修改拒绝覆盖。设置只影响本机模型使用，另一设备需独立配置；不等于阻止配对端接收卡。

聊天输入区沿用带悬停提示和无障碍名称的资料图标，打开“引用共享资料”。选择后加入可移除的引用；发送前重新核对，旧版本或撤销资料不能继续使用。提示已经外发的内容不能撤回、历史回答可在本机阅读；刷新/取回后需要重新选择资料才用于模型。切换会话关闭弹窗并废弃迟到结果。完整数据规则见[用途授权](federation.md#shared-model-use)与[引用边界](federation.md#shared-live-references)。

保存、同步、撤销和删除的结果分别提示，不能把“已保存到本机”写成“两端都已保存”。页内说明删除记录、离线副本和资料范围；技术协议与资源上限引用[权威定义](federation.md#shared-cards-runtime)。没有新增顶栏文字按钮，继续遵守[顶栏图标规则](#workbench-settings)；支持窄屏换行、键盘焦点与减少动画偏好。
